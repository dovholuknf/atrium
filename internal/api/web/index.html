runners

What atrium knows how to start. A command, a working directory, an environment and a way to resume. Nothing about claude, codex or ollama is special-cased.

fixtures ?

Terminals that come up with the daemon, in order, each landing back on the card it used last time.

sources ?

Commands on a timer. Whatever they print becomes cards in the inbox, for you to look at rather than for atrium to act on.

recognisers ?

Paste a pull request, an issue or a ticket and get a launch dialog that already knows the repo, the branch, the title and a first instruction. Nothing about any source system is in the binary: it is all in these rows.

actions ?

A named prompt, offered on every card, sent the same way as anything else you say to a session.

rooms ?

Other machines running their own atrium and reporting into this one. This board holds nothing about them that survives a restart, and their terminals stay where they are.

back it up

Atrium's configuration as one file a repository can hold: harnesses, fixtures, sources, actions, rules, the skin, any terminal themes you brought, the timers and the sharing options. Enough to rebuild this machine from a checkout.

No credentials are in it, and that is not a best effort: the export REFUSES rather than redacting if anything in your configuration looks like one, and says where. So a restored machine still has to be enabled against zrok and still has to enroll a ziti identity. MB in the daemon lines in the browser
The daemon keeps the last few megabytes of every running session and hands the lot over when you attach, so nothing older than that can reach the page at all. The browser then keeps that many lines of it. Whichever runs out first is what you get, and which one that is depends on how long the lines are: fifty thousand ordinary lines is about four megabytes, but one progress bar redrawing itself is a single line and can be megabytes on its own. Megabytes are resident per running session and lines are resident per open terminal, so ten sessions at 64MB is 640MB of atrium. The daemon's half applies to sessions started after you save it. Leave either empty for the default.

add a room

A room is a machine running its own atrium that tells this one what is on it. You add one by running a command there, not by filling in a form here. Nothing is created by this dialog: the room appears in the list the first time it checks in, and disappears again when it stops.

A path on the room, not on this machine. Dialling a service means being somebody on that network, and that identity is enrolled there.
The name is the key. Two rooms sharing one name are one room that flaps, so leave it empty unless the hostname is not what you want to read.
Terminals do not travel. A pseudo terminal cannot leave the machine that made it, so attaching to a runner over there means opening that board. This is the link on the room's row, and without it the row has nowhere to send you.
