- **The recogniser rows and their loader now ship in `scripts/recognisers`, so a pasted GitHub or Bitbucket pull request link can be recognised.** (Repo only, no deploy.) Main's recogniser table is empty, so the rows come from the files: `github.json` (pull request, issue, and a bare repository as the shrug at the bottom), `bitbucket.json` (pull request), `load.ps1` and a README. `load.ps1` PUTs each row to `/v1/recognisers/{id}` and runs under `pwsh` on Windows, macOS and Linux, with `-Root` to rewrite the example worktree paths. The pull request patterns are now anchored: a trailing path, query or fragment (`/files`) still resolves to the same pull request, but extra path in front of `/pull`, or letters glued to the number, no longer match. The rows are not loaded anywhere automatically, and `docs/runtime/scm-design.md` now says so. Item r-new-scm-recognisers-salvage.
