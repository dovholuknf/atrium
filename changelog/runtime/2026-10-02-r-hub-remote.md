- **The room has a stable `hub` forwarder, and cards push to the hub only.** `/git/hub/<host>/<owner>/<repo>.git/...` on the agent listener is forwarded to the hub over the link's `git` kind (`gitsync.HubRemote`). It takes the card from the card's own token and refuses a request without one with its own sentence before anything goes to the hub. Every request to the hub carries `X-Atrium-Card` and `X-Atrium-Card-Chain`, with any the client sent deleted first and the forwarder's Set, and git's bytes are streamed untouched, so the hub's `remote: atrium: ...` sentences reach git as they are. Item r-hub-remote.
- **Card tokens, the small version.** Until the security design's 2c card tokens exist, the room mints a random 256-bit token per card at launch (`gitsync.CardTokens`, memory only, compared in constant time, the forwarder's table holds a hash). It opens the forwarder route and nothing else on the agent listener, is dropped when the card's runner exits or the card is no longer running, and is never in argv, a log, `.git/config` or the card's details. The whole of it sits behind `gitsync.CardAuth` (Mint, Check, Revoke), so 2c replaces it without touching the forwarder. The room also keeps each live card's token in the clear in memory (`hubGit.issued`), so `atrium_git_push` can push with it, and drops it with the card. A card launched before the room last started has no token and must be relaunched. A runner's exit revokes only a token minted no later than that run started, so a resume's new token survives the old run's late exit.
- **The token reaches git by environment, scoped.** A launch adds `GIT_CONFIG_COUNT/KEY/VALUE` with `http.http://127.0.0.1:<agent port>/git/.extraHeader`, never a bare `http.extraHeader`, so a fetch from `origin` or a dependency sends no atrium header (tested against a header-recording server). A harness's own `GIT_CONFIG_COUNT` is continued, and an inherited `GIT_CONFIG_*` is no longer passed to launched runners.
- **`git_push`: `hub` (the default) or `none`.** The room setting (settings API, `git_push`; the design's `git.push`). With `none` the forwarder refuses receive-pack, the advertisement and the POST, and fetch still works. Not exported with the config. An unreadable value reads as `none`. A launch with `outside_code` (or the tag `atrium:outside-code`) gets no token and no git env, and the PR runner's commands and forks never had one.
- **`atrium_git_push {branch}`.** The same push without a shell, for a card's own directory, in the worker set. A plain branch name only (no force, `+`, `:`, tags, delete, `refs/`). It checks `git remote get-url --push --all` (after every `insteadOf` and `pushInsteadOf`) is exactly one URL and the forwarder's, so a second pushurl is refused, and clears the clone's remote and url-scoped proxy settings so a proxy cannot sit between the token and the forwarder. It pushes through `hub` or else `atrium-hub`, and answers git's own report, the hub's refusal included.
- **The room adds `hub` to the clones it syncs.** The sync adds `hub` at the stable URL with the host canonical, follows an agent port change of atrium's own remote, and leaves a `hub` pointing elsewhere alone and adds `atrium-hub`, saying so in the sync detail. On a clone the sync made, `remote.origin.pushurl` is `atrium-refused://origin-push`. An existing clone's origin is not touched, because there is no way to give the operator's yes yet, and the detail says so.
