- **A pull request can get a worktree, with the code from the scm clone path when the room has no checkout of the repo.** (Repo only, no deploy.) New `POST /v1/providers/{name}/pr-worktree` with `{org, repo, number}` makes `<worktree_root>/<org>/<repo>/<branch>`. The head ref and fork flag come from the forge interface. A same-repo PR is checked out on its real head branch and a fork PR on `pr-<N>`. A worktree already on that branch is the answer, `existed: true`. A provider with no checkout of the repo no longer refuses: the code comes through the `atrium_git_clone` path (the `hub` remote added, `origin` push guarded), then the PR head is fetched. A repo that cannot be cloned answers the clone failure sentence exactly, and a missing or logged-out forge CLI answers its own sentence before anything is cloned. The older `/worktree` verb still does not clone. Item r-pr-worktree.
