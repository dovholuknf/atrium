- **Dismissing an automatic new context chip at the wrong moment no longer kills the daemon.** A failed step read
  the chip twice, and a dismissal between the two reads left nothing to read, which panicked the run's goroutine and
  took every supervised runner with it. Only with `auto_new_context` on. (r-new-review-25e40102)
- **An automatic new context that finished records its result.** A context tick between the chip going and the run
  being marked finished read it as dismissed, and the `done` event with `before` and `after` was never written.
  (r-new-review-25e40102)
- **A failed automatic new context keeps the idle handoff it found**, so the next idle park does not ask for another
  one. The keep-alive line on a card reads the new session after a new context, not the old one.
