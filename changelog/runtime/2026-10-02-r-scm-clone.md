- **`atrium_git_clone {url}` makes clones in the operator's scm folder.** The room setting `git_scm_root` (`git.scm_root`, `~/git` on m1mini; POST `/v1/settings`, with `git_credential_helper` for a private repository and `git_credential_hosts`, default `github.com`) holds the folder, laid out `<scm_root>/<host>/<owner>/<repo>`, and unset means the tool refuses and says how to set it. The url is checked (https or `git@host:owner/repo`, no `file:`, `ext::`, option-looking text, `..` or a token), the destination has to stay under the folder after symlinks are resolved, and the clone is an argv slice with `GIT_TERMINAL_PROMPT=0`, https only, bounded in time and output. A clone that fails answers one fixed sentence. Atrium's `hub` remote is added (`atrium-hub` where the clone's own `hub` points elsewhere, which is left alone), and on clones atrium makes `remote.origin.pushurl` is `atrium-refused://origin-push`. Item r-scm-clone.
- **A clone the operator made is left alone until one yes on the board.** The first call asks as a permission on the calling card and answers `asked`; after a yes, `hub` and the origin push guard are added and the clone remembers it (`atrium.adopted`), so there is no second question. A no leaves it untouched. Item r-scm-clone.
- **The credential helper is offered only to listed hosts.** It is passed as `credential.https://<host>.helper`, scoped to the checked host of the clone and only when that host is in `git.credential_hosts` (default `github.com`), so a card that names a host of its own cannot make the room send the operator's credential there. Item r-scm-clone, review M1.
- **Two things to know.** The one yes guards against accidents, not a card that means it: `atrium.clone=made` is read from the clone's own config, so a card that plants a folder under the scm root can skip it. And `git.credential_helper` is a command (`!...` runs a shell) set through `POST /v1/settings`, which has no operator gate until r-new-sec-auth-guard. Item r-scm-clone, review L1 and L2.
