`atrium open <url>` opens the link as a card from any terminal, through the same `POST /v1/open` the board's paste
calls: the worktree, the review and a session in the worktree, on the room the hub picks, or the card the link already
has. It prints the card, its worktree and its address on the board (`<board>/#term=<card>`). With no url it reads the
clipboard (PowerShell on Windows, pbpaste on a Mac, wl-paste, xclip or xsel on Linux). `--attach` attaches this
terminal to the card's terminal over the board's own socket, and Ctrl+] leaves it with the card still running.
`--why`, `--room` and `--runner` pass through. `--show` is the old print, which starts nothing and is the loop for
writing a recogniser. A link the verb does not open yet (an issue, a support ticket) is shown the same way, and
`--start` launches it from what it resolved to, as before. Agents get `atrium_open {url, why}`, which opens on the
agent's own room. Design: `docs/rnd/card-lifecycle-design.md` section 3 and Q10, phase 4.

Test plan:
- `atrium open https://github.com/openziti/ziti-console/pull/967` in a plain terminal. It prints `opened:`, the
  card, the worktree and a board address that opens the card's terminal.
- The same again prints `already open:` with the same card.
- Copy a pull request link and run `atrium open --attach`. The card's terminal draws in this one. Type, see it
  answer, press Ctrl+], and the card is still running on the board.
- `atrium open --show <url>` prints the resolution and starts nothing.
- `atrium open https://github.com/openziti/ziti/issues/1` prints that only a pull request opens as a card so far,
  then the resolution.
