- **The pulls index and its API.** Migrations `0078_pr_review` and `0079_pr_recipe` add the review index and the
  recipe table, with a seeded `default` recipe that stays deleted once deleted. `internal/store/prs.go` holds the rows,
  the run folder (`<reviews_root>/<host>-<org>-<repo>/pr-<n>-<head7>/` with `steps/` and `findings/`) and the recipe
  rules. The new `reviews_root` setting defaults to `reviews/` beside the database. `POST /v1/prs`, `GET /v1/prs`,
  `GET /v1/prs/{id}`, `retry`, `abort` and `start`, plus the drawer routes (findings, edit behind a content hash, walk
  marks, walker), all on the human listener and never held by a board pause. A `PRRunner` interface stands where the
  runner will go, and a stub fails every run as `runner: runner not built`. The contract is `docs/rnd/pulls-api.md`.
  Item r-pr-store.
  For the runner worker: (a) the runner's state moves must use `MovePR` with a `from` list. Abort marks the row
  `aborted` before it calls `Abort()`, so a runner that writes `failed` or `ready` while winding down must not
  overwrite it. (b) A retry of a failed row keeps its `run_dir`, but `RunFolderOn` builds from the current
  `reviews_root`, so the two differ after a root change.
