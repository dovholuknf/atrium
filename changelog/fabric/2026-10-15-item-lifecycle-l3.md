The hub now reads three of an item's steps from git and the builds: `landed` (every commit of the build branch is on `claude/main` on the mirror by ancestry or by patch id, so a cherry-pick counts, at the commit there that carries it), `pushed` (origin's main holds it the same way, so a re-signed copy counts, by one `ls-remote` per pass shared by all items and kept five minutes unless a mirror pass or collect asks again) and `deployed` (the hub and every room the item's code runs on report a build that holds it, scope from deployready's own classification). A room on an older build keeps `deployed` active and is named. A `doc` item, or one whose files are all docs, tests and images, shows `deployed` as skipped with the reason. They are read again after every mirror pass, collect and room attach, and show on `GET /_hub/work/<id>` as `steps`. An item's build branch and kind are set with `POST /_hub/work/<id>` (`{"branch","kind"}`, from the hub's machine). Hub migrations `0023_work_step` and `0024_work_paths`. Item f-item-lifecycle-l3.
