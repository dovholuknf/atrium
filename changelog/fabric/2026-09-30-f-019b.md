- The hub moves code to and from its rooms by FETCH, and nothing is ever pushed. Give the hub a repository with
  `atrium rooms git repos add <name> <checkout>` (the `git_repos` hub setting) and it mirrors that checkout's
  `claude/main` into a bare copy every 30 seconds, serves it to rooms on a new link connection kind, `git`, and asks
  each attached room to sync when it moves and when the room attaches. A room says Git in its hello and the hub says
  it in its welcome, so nothing is ever probed by being refused. The hub collects each room's `claude/*` branches
  (never `claude/main`) into `refs/rooms/<room>` and delivers them into the checkout as `refs/remotes/<room>/claude/*`,
  every five minutes and on demand. It never writes `refs/heads` in the checkout. Ask for either now with
  `atrium rooms git sync <room> [<name>] [--init]` and `atrium rooms git collect <room>`, `POST /_hub/git/sync` and
  `/_hub/git/collect`, or the control tools `atrium_git_sync` and `atrium_git_collect`. None of them takes a path, a
  url, a refspec or a branch, and the hub refuses a `git_repos` entry whose branch is not `claude/main` or `main`.
  Served by `git http-backend` behind `net/http/cgi`, upload-pack only, protocol v0, with the dumb protocol and
  `HEAD` and `refs/rooms` hidden and every setting passed in the CGI environment and none written into a repository.
  Stale ref locks older than the ten minute command bound are removed under the refs each side owns and nowhere else.
