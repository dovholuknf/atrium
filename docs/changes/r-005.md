## Test plan

## @LETTER@. A lean launch keeps only the agents it names

### @LETTER@1. Named agents are available and nothing else is

1. Put `demo-a.md` and `demo-b.md` (frontmatter with a `description`, then a prompt) in `~/.claude/agents` on the room.
2. `atrium_launch` a claude worker in a scratch directory with `lean_agents: ["demo-a"]` and the prompt "list the
   subagent types you can start, names only".

**Expected:** the answer lists `demo-a` and does not list `demo-b`. Only Claude Code's built-in types appear beside it.
The card's tags include `atrium:lean` and `atrium:agent:demo-a`.

### @LETTER@2. Everything else lean drops stays dropped

1. In that worker ask what skills, memory and CLAUDE.md instructions it has.

**Expected:** none of the operator's skills, memory index or global CLAUDE.md. The status line still shows.

### @LETTER@3. A restart keeps the list

1. Restart the room, or exit the worker and reopen its card.

**Expected:** it comes back with the Agent tool and `demo-a` only.

### @LETTER@4. Refusals

1. Launch with `lean_agents: ["no-such-agent"]`.
2. Launch a codex runner with `lean_agents: ["demo-a"]`.
3. Launch a claude worker with `lean: false` and `lean_agents: ["demo-a"]`.

**Expected:** each launch is refused with an error, the first one naming `no-such-agent`, and no card is left behind.
