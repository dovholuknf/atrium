## Test plan

## @LETTER@. A nested claude does not act as its parent card

### @LETTER@1. A nested session ends

1. On a running card, open its Bash tool and run `claude -p "say hi"`, so a second session inherits the card's task id.
2. Let the nested session finish.

**Expected:** the card stays where it was, and its resume id and pid are unchanged. The daemon log has a line
"dropped a session end ... not its runner".

### @LETTER@2. A nested Stop does not take a queued message

1. Queue a message for the card with `atrium tell`, then have the card run a nested `claude -p` that ends a turn.

**Expected:** the message is still queued after the nested turn ends, and the card's own next turn end delivers it.

### @LETTER@3. A nested permission request is still gated

1. From the same card, run a nested `claude -p` that makes a gated tool call.

**Expected:** the request is answered by the usual chain (rule, auto mode, or the operator), and the card's pid
does not change.
