## Test plan

## @LETTER@. Every terminal start is a run, and its exit is filed once

Use a throwaway room, never the live one. Nothing here should look different from before.

### @LETTER@1. A restart, a stop and a reopen still work

1. Start a card with a runner and open a shell beside it. Type in both.
2. Restart the runner from the card menu, then close the shell.
3. Stop the room with `atrium stop`, start it again, and let the fixture reopen.

**Expected:** the runner and shell behave as before, attach replays the same scrollback, and the card is filed dead
once when the runner ends, with one `exited` event in its history per runner end. Closing the shell adds no event and
does not move the card.

### @LETTER@2. Each start has its own run

1. After @LETTER@1, open the room's database copy and read `pty_run` for the card.

**Expected:** one row per start, kinds `runner` and `shell`, `host` empty, and every row whose terminal ended has
`filed_at` set. A runner and a shell on the card never share a `run_id`.

### @LETTER@3. `pty_host` does nothing yet

1. `POST /v1/settings` with `{"pty_host": true}`, then start a card.

**Expected:** the card starts in this process, the daemon log says no host is built yet, and behaviour is unchanged.
Turn it back off afterwards.
