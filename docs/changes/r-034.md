## Test plan

## @LETTER@. Standing rules for MCP tools

### @LETTER@1. A server rule and a narrower deny

1. Add a rule `mcp__mercurius__*` approve, then `mcp__mercurius__discourse_discourse_create_user` block, from the
   rules page or `POST /v1/rules` with an empty prefix.
2. From a gated session call `mcp__mercurius__discourse_discourse_search`, then `..._create_user`.

**Expected:** the search is approved with no prompt. The create is blocked. The history row for each names the tool
pattern as the decider, not `*`.

### @LETTER@2. Import from settings.json

1. Put `mcp__mercurius` and `mcp__mercurius__discourse_discourse_get_*` in `allow`, `mcp__mercurius__discourse_discourse_create_*`
   in `deny`, and `mcp__a__t(x)` in `allow`.
2. Preview and import the Claude settings.

**Expected:** three rules are added. The `(x)` entry is skipped as "MCP rules match the tool name, not its arguments".
A deny `mcp__*` is offered only with include broad.

### @LETTER@3. An ask shadows an allow

1. Put `mcp__mercurius__*` in `allow` and `mcp__mercurius__discourse_discourse_create_topic` in `ask`, then import.

**Expected:** the server allow imports. No rule is made from the ask. Nothing is dropped, because the ask is narrower.
Swap it so `mcp__mercurius__*` is the ask: the allow is skipped as "shadowed by ask".

### @LETTER@4. Approve forever on an MCP call

1. Let an MCP call reach the queue and press "always".

**Expected:** the new rule is the exact tool with prefix `*`, and a call with different input is approved.

### @LETTER@5. A tie goes to block

1. Add `Bash` rules `go build*` approve and `go build?*` block.
2. Run `go build ./...` from a gated session.

**Expected:** blocked, whichever rule was added first.
