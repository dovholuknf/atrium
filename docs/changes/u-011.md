# u-011: usage tab cache reads toggle

## Changelog

- The usage tab no longer counts cache reads by default. They were 1451M of a day's tokens against 24k uncached in, so they swamped every chart. Counted tokens are uncached in + out + cache write 5m + cache write 1h (`ucCounted`, beside `ucTokens` in `usage-charts.js`, the one place the rule lives).
- A `cache reads` button at the right of the range bar, with the legend swatch, turns them back on. Stored as the daemon setting `usage_cache_reads` (default off, in `GET/POST /v1/settings`, broadcast on the `settings` event so other tabs follow). With it on the tab is as it was.
- Off: burn rate, by card and the card details' 24h chart use counted tokens; tokens by kind covers the four counted kinds and adds `cache reads N · not in these charts · P% of input was served from the cache`; tokens by cause shows counted tokens with cache reads as a dim column. The burn bar hover still lists all five kinds.
- Fixed "0 calls" on every cause row: `ucSums` now carries `replies` (needs `replies` in the store's `UsageSums`, done separately).

## Test plan

- `go test ./internal/api -run UsageCacheReads`: default false, round trip.
- `HEADLESS_ONLY=usageCacheReads node scripts/test-board-headless.js`: default off (four kinds, the line, five on hover), toggle on (five kinds, line gone), the setting posted, a cause row shows calls.
- By hand: open the usage tab, press `cache reads`, reload and open a second tab; both follow the setting.
