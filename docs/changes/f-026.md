## Test plan

## @LETTER@. A room with no certificate cannot take a proven room's name

Needs a hub on an overlay (zrok or ziti) with `overlay_legacy` at its default `allow`, one room that joined with a
new-form join string (so it has a certificate), and a second machine holding an OLD-form join string.

### @LETTER@1. The proven room is attached

1. With the proven room attached, start the second machine on an old-form join string that names the same room.

**Expected:** the second machine is refused with a sentence saying the name belongs to a room with a certificate. The
proven room stays attached and `proven`. `atrium rooms log` shows ONE `room-unproven` line saying `refused over
<overlay> without a certificate: a room with a certificate is attached under that name`, however often the second
machine redials in the next ten minutes.

### @LETTER@2. The proven room is away

1. Stop the proven room, and leave the second machine redialling.

**Expected:** still refused, and the `room-unproven` line says `that name enrolled a certificate`. The name never
shows as attached.

### @LETTER@3. A room that never enrolled is unchanged

1. Attach a room on an old-form string whose name has never enrolled a certificate.

**Expected:** it attaches as before, listed as unproven, with the usual `room-unproven ... attached over` line.

### @LETTER@4. An upgraded hub remembers who enrolled

1. On a hub whose rooms joined before this build, install it and restart the hub.

**Expected:** a name with a `joined` line in `atrium rooms log` is refused on the old path from the first attach. A
name whose `joined` line has aged out of the log is refused on it once that room attaches with its certificate.
