## Changelog

- **A report of the repaints that still overwrite rows on the board's terminal.** See `docs/backlog-2.md` item 74.

  `GET /v1/tasks/{id}/scrollback/text?repair=report` lists every bare `ESC[H` full-screen repaint in a card's ring that
  started from a later row than the screen held, which is the loss item 74 traced to conhost's resize repaint. It is
  the measurement that decides between option 2 (OpenConsole ConPTY) and option 3 (a replay-only repair), now that the
  height hold has stopped the big losses. It is a diagnostic and NOT the repair. Nothing is spliced: history, attach
  replay and `/scrollback/text` without the parameter are byte-identical to before. The outcome `repaired` means
  "would be repaired", and `added` is the rows that would be spliced.

  The body is tab separated with no banner: a header line, one line per candidate (`offset`, `rows`, `cols`, `cut`,
  `outcome`, `k`, `added`, `why`), and a `totals` line of `outcome=count` pairs then `added=N`. The outcomes are
  `repaired`, `resize-filed`, `no-match`, `ambiguous`, `cancelled` and `incomplete`. The report always renders in
  `screen` mode, ignores `mode`, `ansi` and `collapse`, takes its bytes and cuts from one `ReplayCuts` call, and
  honours `?kind=shell`. The detector lives in `internal/daemon/screen_repair.go` behind `screen.rep`, which only the
  report sets, so every other user of the grid pays a nil check. Adding the splice later is one addition in
  `repairWatch.close`.

## Test plan

## @LETTER@. The repair report

### @LETTER@1. Read the report on a live card

1. Pick a card that has run for a while, and open `/v1/tasks/<id>/scrollback/text?repair=report` in a tab. Use
   `&kind=shell` for the card's shell.
2. Read the last line. `repaired=N` is how many repaints overwrote rows that a repair would have kept, and `added=N` is
   how many rows that is. Note both, and read them again a day later: the totals are cumulative over the ring, so two
   readings compare at a glance.
3. For each `repaired` line, `k` is how many rows the repaint started below the top of the screen. A line with a `cut`
   other than `-` sits at a height change, and `added` there is `k` minus the rows the resize already filed.
4. Treat a `repaired` line as a possible false positive when the ring around its `offset` shows Claude collapsing a
   block or a tool's output shrinking. The rule cannot tell those apart when the rows match.

**Expected:** a header, one line per candidate and a `totals` line, with no `[atrium]` banner. A card that has never had
its height changed reports `repaired=0`.

### @LETTER@2. Nothing else changed

1. Open `/v1/tasks/<id>/scrollback/text` without the parameter, before and after step 1.
2. Reload the pane so it reattaches.

**Expected:** the text is identical both times, and the rows a repaint overwrote are still absent from history, because
the report measures and does not repair.
