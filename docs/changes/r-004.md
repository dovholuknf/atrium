## Changelog

- **A card never changes directory, and the worktree-gone reaper checks the launch directory only.** See
  `docs/backlog-2.md` r-004.

  The reaper ended a live worker because the card's `Worktree` followed the session's `cd`, and a `.git` seen in a
  subdirectory made the launch root read as a `.git` that went away. Three changes. A card's `Worktree` is its launch
  directory and permission, message, session and activity reports no longer overwrite it. The one exception is a card
  with no worktree at all, such as a session joined by `atrium join`, which takes the first one reported and then
  never moves. Launching a card into another directory, and claiming an offered card, still set it on purpose. Every
  runner now remembers the directory it was started in, not only a resume, and the reaper asks about that one. And the
  remembered `.git` is keyed by card and directory, so one directory's `.git` never makes another read as gone.

## Test plan

## @LETTER@. A card stays where it was launched

### @LETTER@1. A cd does not move the card

1. Launch a subagent card in a directory with no `.git` that has a subdirectory holding a repository.
2. In the session, `cd` into the repository, run a command that needs permission, then `cd` back and run another.
3. Read the card's worktree on the board.

**Expected:** it is still the launch directory, and the card is not wound down.

### @LETTER@2. A removed launch directory still ends the worker

1. Launch a subagent card, then remove its launch directory from outside.

**Expected:** after two reaper ticks the runner is asked to leave.
