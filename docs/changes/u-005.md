## Test plan

## @LETTER@. A pasted link opens as a card

### @LETTER@1. Paste opens at once

1. On the board (not in a box or terminal), paste `https://github.com/openziti/desktop-edge-win/pull/1095`.

**Expected:** no bar and no launch dialog. A card naming the pull request appears at the top of running and of the
terminals list, saying each step (reading, cloning or finding the clone, fetching, making the worktree). It turns into
the real running card, attached. No toast lingers over the board.

### @LETTER@2. A failure stays on the card

1. Paste a pull request link that cannot be fetched (a number that does not exist).

**Expected:** the pending card turns red with the reason and offers edit, again and dismiss. No dialog comes up.
`edit` opens the launch dialog filled in, `again` repeats the open, `dismiss` drops the card.

### @LETTER@3. The dialog, cut down

1. Ctrl+Alt+R, paste a link, Shift+Enter. Then open "+ new agent".

**Expected:** no throwaway, no clean up when done, no "don't ask again", no second link box, no title, tags or why.
Model and effort share one line under the runner. The first instruction is visible without unfolding anything.

### @LETTER@4. Room default on the hub

1. On the hub's ALL view, paste a link to a repo that one room already has a clone or worktree of.
2. Paste a link to a repo no room holds.

**Expected:** the first opens on the room holding the repo. The second opens on the room last launched on, never on
"least busy". On a board scoped to one room, it opens on that room.

### @LETTER@5. The operator's own clone is adopted

1. Have a clone of the repo at the place gwt would put it, made by hand (no atrium marks).
2. Paste a pull request link for that repo.

**Expected:** the open goes on without asking. The room log says the clone was adopted, and the clone's origin push
URL is guarded the same way as an atrium clone.

### @LETTER@6. Close says what it deletes

1. Close a card whose worktree holds a commit that is on no remote.

**Expected:** the dialog says "Closing deletes" with each row in words (the worktree, the branch here, and the branch
on the hub once the hub branch inventory lands), a warning line about the unpushed work first, and the worktree as a
row with keep, stash or delete.

### @LETTER@7. Close deletes the clone the open made

1. On a room with no clone of a repo, paste a pull request link for it, so the open clones it into the scm folder.
2. Close the card.
3. Repeat, but before closing add a second worktree off that clone by hand (`git worktree add`).

**Expected:** the first close lists "the clone it made" under "Closing deletes" and the clone folder is gone after it.
The second keeps the clone, the preview lists it under Kept with "1 other worktree hangs off it", and the close warns
the same. A clone the operator made (adopted, not cloned) is never deleted.
