# u-009b: the board's last polls, driven by events

Follows u-009 (`docs/backlog/ui/u-009.md`). Three things still ran on a clock, and now none does.

## What changed

- **Walk drawer** (`js/walk.js`). The 3s `dockSchedule` loop and `window.__walkPollMs` are gone. The findings folder
  is read again on `dockKick` (a `task` event for the docked card, trailing 1s so a burst is one read),
  on the tab becoming visible, and on the 60s resync (`dockResync`). A kick that lands during a read queues one more
  read. Findings are files an agent writes and no event says one landed, so the card's own events stand in. A
  dedicated event from @runtime would be exact: see "Ask".
- **`rooms` event** (`js/rooms.js`, `js/settings-spine.js`). `paintHubRoomsEvent` paints from `attached` and
  `inventory` through `applyHubRooms`, the tail `loadHubRooms` always ran. No `attached` (an older hub) falls back to
  `loadHubRooms`, and no `inventory` fetches just the inventory. The alert reseed still runs first. The resync keeps
  its one `loadHubRooms`, which a board scoped to one room needs because it has no `rooms` events.
- **`health` event** (`js/settings-spine.js`). `applyHealth` is what `/v1/health` was applied with, now shared with
  `onHealthEvent`. The `SETTLING_RECHECK` timer is removed. `/v1/health` is still read at first paint, on a stream
  reopen and on the resync.
- **Audit**: see the table in `docs/backlog/ui/u-009.md`.

- @runtime: a findings-changed event for a card's worktree, so the walk drawer need not infer from `task` events.
