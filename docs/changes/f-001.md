## Test plan

## @LETTER@. A dropped request does not halt the hub

### @LETTER@1. The automated cover

1. `go test -tags integration -run 'TestACancelledCallerDoesNotHaltTheStore|TestARealFailureStillHalts' ./internal/hubstore/`
2. `go test -tags integration -run TestAHaltedHubKeepsTheRoomsItKnew ./internal/cli/`

**Expected:** both pass. A cancelled or timed-out caller halts nothing and its push-log write lands. A closed
database still halts. A halted hub still admits a room it knew and refuses one it did not.

### @LETTER@2. A git push whose client is killed

1. With a hub and a room attached, start a `git push` to the hub mirror and kill it with Ctrl-C mid push.
2. Read `hub.err` and the board.

**Expected:** no `THE STORE HAS HALTED` line. The room stays attached and `atrium_status` still answers.

### @LETTER@3. A hub whose store halts keeps its rooms

1. On a scratch hub, make the store fail (for example, delete or lock `hub.db` from under it, then add a room).
2. Watch the rooms and a session's control tools.

**Expected:** `THE STORE HAS HALTED` is logged once. Known rooms stay attached, a room restarted reattaches, and
control tools still answer. A room the hub never made is refused.
