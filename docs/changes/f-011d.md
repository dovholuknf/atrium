## Test plan

## @LETTER@. A restarted daemon reattaches to its runners (pty_host on)

Use a throwaway room, never the live one. Turn the `pty_host` setting on first.

### @LETTER@1. Restart the daemon, keep the runners

1. Start a card with a runner and open a shell beside it. Type in both, so each has scrollback.
2. Stop and start the daemon (not the host, not a kill of the host).

**Expected:** both terminals are still running. Attach replays the same screen and scrollback, then follows live with
nothing lost or repeated. A resize after the restart lands before any byte at the new size.

### @LETTER@2. A runner that ends while no daemon is connected

1. With the daemon down, let the runner exit. Start the daemon.

**Expected:** the card is filed dead once, with one `exited` event and the same tail and why as a live exit. The host
no longer lists the run.

### @LETTER@3. The host cannot be reached

1. Point `pty_host` at a missing binary and launch a card.

**Expected:** the launch succeeds with an in-process terminal.

### @LETTER@5. Turning the setting off while the host holds runners

1. With `pty_host` on, start a card, then turn the setting off and restart the daemon.

**Expected:** the card has one runner, the host's, and no second copy is started in the daemon.

### @LETTER@4. The host idles out

1. Run `atrium ptyhost --state-dir <temp dir> --idle-exit 5s`.

**Expected:** it logs `up`, then exits about five seconds later with `idle for 5s with no pty and no daemon`.
