## Changelog

- **A link clicked in a terminal reuses its tab.** See `docs/backlog-2.md` item u-006.

  Clicking a URL in a terminal used to open a new tab every time, so a review walk that clicked one GitHub deep link
  per finding left dozens open. The link now opens into a named window: one per pull request for
  `github.com/<org>/<repo>/pull/<n>` and anything under it, and one per origin plus path for anything else. The
  helper is `openLinkReused(url)` in `js/terminal-links.js`, which the review walk's `o` and `C` keys also call. It
  uses `window.open(url, name)` and nulls the opened window's `opener`, because Chrome ignores the name under
  `rel=noopener`. `rel=noreferrer` went with it, since it forces a new tab too, so the referrer is now withheld for
  the whole page by `<meta name="referrer" content="no-referrer">`. Nothing in the daemon reads `Referer`.

## Test plan

## @LETTER@. A terminal link reuses its tab

### @LETTER@1. Two links in one pull request

1. In a terminal, print two links to the same pull request, for example
   `https://github.com/openziti/zrok/pull/1277/files#diff-aR165` and `.../pull/1277/files#diff-bR61`.
2. Click the first, then click the second.

**Expected:** the second click loads into the tab the first opened and brings it forward. No second tab appears.

### @LETTER@2. A different pull request, and a non-GitHub link

1. Click a link to a different pull request, then a link to any other site.

**Expected:** each opens its own tab, and clicking either again reuses it.

### @LETTER@3. The board's address is not sent

1. Open the developer tools network panel, click a terminal link, and read the request headers of the page it
   opens, or open a page that echoes them.
2. In the opened tab, run `window.opener` in the console.

**Expected:** there is no `Referer` naming the board, and `window.opener` is `null`.
