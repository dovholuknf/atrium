## Test plan

Test plan @LETTER@: provisioning sets a room's allowed folders. Needs the `atrium room folders` verb and the launch bound (runtime's) deployed on the room under test, then the scripts here. Run against m1mini (macOS, sh) and sg3 (Windows, PowerShell). Offline first: `pwsh -NoProfile -File scripts/test-room-folders.ps1` prints `all N checks pass`.

1. On a room whose atrium has no `room folders` verb yet (an older build), `pwsh -File scripts/provision-room.ps1 <target> -Name <room> -AllowedFolders /tmp` prints `provision folders warn this atrium has no room folders verb yet ... run: ssh <target> ... room folders allow /tmp`, no `fail`, and the run still ends `provision done ok` (or its usual exit).
2. After deploying the new binary to a room that is already provisioned: `provision-room.ps1 <target> -Name <room>` with NO folder flag prints `provision folders skip a rerun keeps the list as it is` and changes nothing: `ssh <target> <atrium> room folders list --json` still says `enforced:false`.
3. `provision-room.ps1 <target> -Name <room> -AllowedFolders <clone>,<clone>-worktrees` prints one indented line per folder (`allowed <dir>`, `trusted <dir>`), then `provision folders done ...`. `list --json` now says `enforced:true` with both roots, and `~/.atrium/provision/manifest.json` on the room has `allowed_folders` listing them. Run it again: `provision folders ok ... (all were already in the list)`.
4. A brand-new provision (after `-Remove`, then provision with no folder flag) allows the clone, `<clone>-worktrees` (created) and WORKTREE_ROOT when the room has one. Check the three roots with `list --json`.
5. `-AllowedFolders ~` or the room's home prints `provision folders warn <home> was skipped: ...` naming it. A missing folder does the same. The folders that were fine are still allowed.
6. `-AllowedFolders relative/dir`, `-AllowedFolders /`, `-AllowedFolders "/a;/b"`, and `-AllowedFolders /srv -Remove` (or `-Restart`, `-SmokeOnly`) all exit 1 with `provision args fail` before ssh is tried.
7. With the list enforced the smoke runs in the clone and passes (`provision smoke:claude ok`), then `provision smoke-outside ok <room> refused a launch in <home> (HTTP 4xx): ...` with an error that names the roots. `board` shows no leftover smoke card. On a room with no list (or the old binary) it prints `provision smoke-outside skip ...` and the smoke is as before.
8. `provision-room.ps1 <target> -Name <room> -SmokeOnly -SmokeCwd <a folder outside the list>` prints `provision smoke:claude warn -SmokeCwd ... is outside <room>'s allowed folders` and launches nothing.
9. In a claude-launched card on the room in a folder from the list, the first prompt is the task, never a trust dialog. The same for a worktree under `<clone>-worktrees`.
10. `provision-room.ps1 <target> -Name <room> -Remove` prints `provision folders skip left alone: ...` and the list is still there in `list --json` if the database stayed.
11. `pwsh -File scripts/room-check.ps1 <room>` prints `room-check allowed-folders ok <room> launches only in ...` for a room with a list, `warn no allowed folders set ...` with the fix command for a room with none (exit code unchanged), and `skip ... no room folders verb yet` on an old atrium. `room-check.ps1 <room> -Fix` alone does not set a list. `-Fix -Yes` does (`allowed-folders done`), and a second run is `ok`.
