## Changelog

- **The file-link tip no longer flickers while the terminal repaints.** See `docs/backlog-2.md` t-001.

  xterm drops the link under the pointer whenever its row is redrawn, which fires the link's `leave` and then asks
  for it again, which fires `hover`. The tip hid on `leave` and came back after the half second hover delay, so
  output touching the hovered row made it vanish and reappear. `leave` now hides after a grace of 150 ms, and a
  `hover` on the same path inside that window cancels the hide and leaves the tip up.

  A different path, a click that opens the file, the pointer leaving the terminal and a page scroll still hide or
  replace the tip at once. The change is local to `js/terminal-links.js`: no other tooltip on the board is touched.

## Test plan

## @LETTER@. The file-link tip stays up across a repaint

### @LETTER@1. Repaint under the pointer

1. Attach a terminal on a card with a directory and print a line that names a file in it.
2. Hover the path until its tip shows, then have the runner repaint that row while the pointer stays put.

**Expected:** the tip stays on screen the whole time. It does not vanish and come back.

### @LETTER@2. It still hides when it should

1. With the tip up, move the pointer onto a different path, then onto blank terminal, then out of the terminal.
2. Hover again and click the path, then hover again and scroll the page.

**Expected:** a different path replaces the tip at once, blank terminal hides it within about 150 ms, and leaving the
terminal, the click and the scroll hide it at once.
