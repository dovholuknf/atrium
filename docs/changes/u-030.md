## Test plan

## @LETTER@. The hub notify command and the board's presence

### @LETTER@1. The gear row draws on a hub
Open the gear, then notifications, on a board served by a hub. A row "notify command (on the hub)" shows an enabled box, the command with one argument per line, save, send a test, and the status in words: last ok, last error, failures in a row, why it was switched off if it was, sent, dropped and held back counts, and how many board tabs are visible now. The hint says the command runs ON THE HUB MACHINE as the hub's user and that atrium keeps no credential.

### @LETTER@2. Save and test
Edit the command, untick enabled, press save: the row says saved and the status repaints from the hub's answer. Press send a test: the exit code, whether it worked, the time in ms and the command's output appear under the buttons. An edit you have not saved is still in the box afterwards. Nothing refreshes on a timer: the row is read when the gear opens, after save and after a test.

### @LETTER@3. No hub, no row
On a board served by a room with no hub the row is not drawn. On a guest link (one terminal) it is not drawn and no request goes to `/_hub/notify` or `/_hub/presence`.

### @LETTER@4. Presence
On a hub, open the board in two tabs and read `visible_tabs` in the gear: it says 2. Switch one to another browser tab, reopen the gear on the first: it says 1. Close a tab: the count drops. Reload a tab: it is still one tab, not two. The event stream request carries `?tab=<id>`.

### @LETTER@5. An idle board asks for nothing
Leave the board open a minute in the background with the network panel open. No `/_hub/presence` request appears on a clock, only on load, on the tab hiding or showing, and on leaving the page.
