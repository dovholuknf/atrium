## Test plan

## @LETTER@. Resume ids, replies and hook names

### @LETTER@1. A claim from nowhere keeps the holder

1. Start two cards and let one hold a conversation id.
2. Have a hook that names a card this room does not hold claim the same id by task id.
3. The first card still holds its id and resumes normally.

### @LETTER@2. A bad resume id is dropped

1. Put a made-up resume id on a shelved card and resume it from the board.
2. The runner fails at startup and atrium starts it fresh.
3. Shelve and resume it again: it does not retry the made-up id.

### @LETTER@3. Replies errors

1. Open a card's replies and read a transcript-backed reply.
2. Ask for the replies of a card id that does not exist: the answer is 404.
3. Make a card's transcript unreadable and reload: the screen text shows, and the daemon log says why once.

### @LETTER@4. Hook names

1. In a directory with no ATRIUM_AGENT_NAME, run a gated tool call: the card is named for the directory.
2. Finish that card, start a new session in the same directory: it gets its own card and the finished one stays done.
