# u-014: usage tab grouped by department and director, tokens per accepted item

Code: `js/usage-groups.js` (new), small hooks in `js/usage-charts.js`, a script tag in `index.html`, a few rules in `css/files.css`.

- **Group by.** The select sends `group=dept` or `group=launcher`; each bucket's `groups` become one `ucmini` per group, sorted by `ucShown`. Keys: `""` is "no department" (dept) or "clint" (director); `@before` is "before grouping". A room that answers with rows but no `groups` gets one dim line.
- **Click a group.** The answer holds sums per group, not which card is in which group, so the card list is filtered by what the board knows of each card now (dept tag, launcher). A pruned card drops out of a filtered list.
- **Live events.** While grouped, a `usage` event marks the view stale and triggers at most one re-read per 5s, trailing (min 500ms). No polling.
- **Per accepted item.** `GET /v1/usage/items?since=` for the tab's range: a table, median footer, "N accepted items have no card on record", a hint on rows with split > 1. A 404 replaces it with one dim line. Items carry no department, so the table is not grouped by department; the tab says so.
