# u-019: the phone terminal follows the on-screen keyboard

## Changelog

- The phone terminal, in the normal phone view and in full screen, is now as tall as the visual viewport, so the
  on-screen keyboard no longer covers the bottom of the terminal or the key bar. The key bar sits just above the
  keyboard. `phoneVVSoon` (js/terminal-links.js) sets `--vvh` and `--vvt` on `:root` from the existing
  visualViewport resize listener, once per frame and on a height change only, never on a visualViewport scroll.
  `body.term-phone` and `body.term-full` take their height from `--vvh`, falling back to `100dvh`.
- The viewport meta gains `interactive-widget=resizes-content`. On Chrome and Brave for Android the layout viewport
  now shrinks with the keyboard on every tab, not only the terminal, so the board, stack and tabs fit above the
  keyboard rather than sliding under it. Both paths agree on the height. iOS Safari ignores it and uses `--vvh`.
- `keepCursorInView` is unchanged: once the layout shrinks the pan container is no longer covered, so its
  keyboard padding computes to zero and the cursor row sits just above the key bar. It still pads where the layout
  did not shrink.
- The grey bar above the key bar was the pan container's own (`#t-screen.phone`, `overflow: auto`) scrollbar. It is
  hidden on a phone (`scrollbar-width: none` and `::-webkit-scrollbar`).

## Test plan

- `phoneKeyboard` in scripts/test-board-headless.js: with the visualViewport height cut by 300px, in the phone view
  and in full screen, the key bar's bottom is at or above the visual viewport's bottom, the cursor row is above the
  key bar, restoring the height restores the layout, no resize frame is sent, and the pan container has no scrollbar.
- By hand on a phone (Brave for Android, and iOS Safari): tap the terminal, and check the key bar rides above the
  keyboard in both views, the cursor row is visible, and the stack and board tabs still fit with a keyboard up.
