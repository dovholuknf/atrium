## Why these keep failing in CI, and what would stop it

1. Tests are written and run only on Windows, and CI is the first Linux run. Case-sensitivity bit here. A required
   Linux job on every branch push, not only main, would catch this before merge (`.github/workflows/ci.yml` already
   has the matrix, so the change is: have the worker run `scripts/ci.sh` on a Linux room before it reports done).
2. Package-level hooks (`stopAfterReport`, `exitOnReportDelay`) are mutated by tests that run in parallel with
   timers still alive from earlier tests. Make the hook a field on `Daemon` instead of a package variable and the
   whole class of leak goes away; until then each recorder must check the daemon it was installed for.
3. Wall-clock ceilings calibrated on one machine fail on any slower one. The scale factor fixes this for hosted
   runners. Re-measure the ceilings from a CI artifact (timings.tsv) rather than a dev box.
4. Lint-style checks (titles, PowerShell parse) are only in ci.sh, so a worker that skips it pushes a red main.
   Run `scripts/check-titles.sh` and `scripts/check-powershell.ps1` from the pre-push hook, which takes under 5s.
