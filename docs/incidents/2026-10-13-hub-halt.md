# 2026-10-13: a dropped request halted the hub

## Summary

A canceled request context on the hub was treated as a storage failure, so one dropped request halted the hub's store.
With the store halted the room listener closed, every room was refused and the control tools died for every session. The
hub was killed at 13:44 and the fix landed as f-001 (`cbdeceec`).

## Timeline

All times are 2026-10-13, from `hub.err`. Anything not listed here is not recorded in the sources.

- 13:00:22 to 13:00:23: rooms `sg4-control`, `claude-sg4`, `m1mini` and `sg3` attached.
- 13:05:47, 13:10:57, 13:11:17: launches timed out, each logged as `POST /v1/launch: context canceled`. Two more
  followed at 13:22:06 and 13:25:56.
- 13:32:26: `POST /v1/tasks/01a1363f-bfa2-7f1d-9368-481f9c723d03/report: context canceled`.
- 13:32:30: `THE STORE HAS HALTED: context canceled`, then `the room listener stopped: accept tcp [::]:7779: use of
  closed network connection`.
- 13:32:32 and 13:32:33: every room was let go, for example `letting "sg4-control" go: this hub has no room called
  "sg4-control"`. The `room-detached` writes failed with `the hub's store is halted: context canceled`.
- From 13:32:33: board reads failed with `GET /v1/tasks: no room is attached` (also `/v1/shares`, `/v1/permissions`
  and `/v1/settings`), and the control tools were dead.
- 13:44: the hub was killed. The last log lines before the kill are still `no room is attached`.

## Root cause

A canceled request context was treated as a storage failure. The report POST at 13:32:26 was canceled, the store
saw `context canceled` on its next write and halted, and a halted hub closed the room listener and forgot which
rooms it had made. Every room then failed the room check even though the hub had created it.

## The fix

f-001, commit `cbdeceec`. A cancel or timeout from a caller no longer halts the store, and push-log writes finish
whoever stopped waiting. A hub whose store does halt keeps its room listener open and keeps the rooms it knew
attached, so control tools still answer. A room the hub never made is still refused. A closed database still halts.
The test plan is in `docs/changes/f-001.md`.

## What was lost

The chatter-rename and r-005 workers died at 13:44 after committing, with no report. Their commits were merged
(chatter-rename `28cd4b76`, r-005 close-workflow design `68667bd3`). The sources also note that two sg4 cards were
gone at the 13:44 check, with their branches already pushed to the hub, and that the interview card for rnd-005 was
not launched because rooms m1mini and sg3 were down.
