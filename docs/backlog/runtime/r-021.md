# r-021. The card popup shows the old conversation's context after a /clear, and one card holds another's resume id (bug)

Status: part 1 BUILT 2026-09-29 on `claude/r-021`. Part 2 diagnosed, fix proposed, not built. Owned by @runtime.
Room-side.

## 1. The popup's context after a /clear (built)

@rnd's popup said 709k while its status line said 101k, right after its 17:23 new-context cycle. `usageFor`
(`internal/daemon/usage.go`) read the transcript by `t.ResumeID`, and after a /clear the resume id stays on the old
conversation until the new one's first Stop. Item 62 fixed the same thing in `contextsize.go` with
`d.ctx.sessionOf(t)`, which prefers the session the runner last started. `usageFor` now uses it too.

The per-session rows and the totals do not have this problem: rows are written by the Stop hook, which moves the
resume id before the row is recorded, and the totals are per card. Test: `TestUsageContextNowFollowsTheStartedSession`.

## 2. One card holding another card's resume id (diagnosed)

The orchestrator saw its card hold @merge's resume id 18fa6feb (both cards run in
`D:/git/github/dovholuknf/atrium`), so @merge could not be resumed ("resume-busy"). After the restart the live
database has 18fa6feb (@merge's conversation, its scratchpad paths say so) stored on an old `done` card, `01a08117`,
whose wire name is plain `atrium`, not on @merge's card.

The cause: a hook that cannot see `ATRIUM_AGENT_NAME` (a session started outside atrium's environment, or a
subprocess of one) names itself after its directory, and the directory here is `atrium`. The Stop and turn path
(`messages.go`) and a session hook with no task id then find the card by `Register(obs)`, on that wire name, which
matches whichever card in the same checkout is called `atrium`. Then `SetResumeID` stores the conversation there. Two
cards in one directory make it a coin toss.

Proposed fix, for @rnd before building:

- A hook that carries `ATRIUM_TASK_ID` is bound to that card by id on EVERY path, not only the session hook, which is
  `Observe` rather than `Register`. The Stop and turn path gains the task id.
- A resume id already held by another live (not archived) card is never stored on a second card. `SetResumeID`
  refuses it and logs both cards, so a stray hook cannot steal a conversation.
- `Register` does not match a `done` or archived card by a directory-derived name.
