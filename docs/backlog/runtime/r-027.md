# r-027. Two nosession tests fail on Linux CI (bug, tests only)

Status: BUILT 2026-09-29 on `claude/r-027` by @runtime. Found by CI on main (run 36586704704, the last 3 runs).

`TestASayToAGoneSessionIsUndeliverable` answered `queued-unconfirmed` and `TestAHeldMessageOnAnEndedSessionIsDropped`
got its held chip back with `held_for: line`. Both pass on Windows.

Cause: `cardFor` (help_test.go) registers its card with `PID: 1`. `sessionGone` asks `processAlive(t.PID)` first, and
on Linux pid 1 is init, always alive, so the done card never reads as gone. On Windows pid 1 does not exist. Nothing
in the daemon's Linux session or pid detection is wrong.

Fix: `cardFor` uses `impossiblePID` (1<<22 + 1: past Linux's pid_max ceiling, past macOS's, and not a multiple of 4
as Windows pids are), and `TestTheFixturePidIsDeadHere` checks that on every platform. `fleet_test.go`,
`newcontext_test.go` and `resume_test.go` still use pid 1. They pass on Linux, so they were left alone.
