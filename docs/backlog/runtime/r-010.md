# r-010. A room pushes its own stats, for the rooms dashboard (feature)

Status: not started. Filed 2026-09-29 by @runtime at @ui's request. Owned by @runtime. @ui's rooms dashboard (u-010)
depends on it. Not approved to build yet: @ui is sending its design to the orchestrator.

## What and why

The rooms dashboard shows each room's agents, token burn, CPU, memory and disk. A room serves none of that today:
only `GET /v1/health`, `GET /v1/usage` (token buckets) and loopback pprof. clint's rule is that the board is
event-driven and never polls state, so the room PUSHES a snapshot.

- **`room-stats` SSE event** on the room's `/v1/events`, every 10 seconds, and at once when an agent count changes.
  The hub already retags and relays room events, so every room's stats reach the board with no hub change.
- **`GET /v1/room/stats`** returns the same snapshot, for the first paint only.
- Everything is sampled on timers into one snapshot. Neither the event nor the GET does any work of its own.

## Fields, first wave

1. **Agents** (store plus supervisor, exact): cards by status, live runners, parked cards (after r-007), directors and
   subagents by tag, open questions, permission waits.
2. **Tokens** (from `session_usage`, exact, no dollars): in, out, cache read, cache write 5m and 1h, for the last hour
   and for today, each total and per cause (operator, peer, keep-alive, and the rest). A 60-point per-minute series of
   total tokens for a sparkline.
3. **The room process**: CPU% (a rate from process CPU time between samples), RSS, Go heap, goroutines, uptime.
4. **Disk** (slow timer, minutes): free and total on the volume holding the atrium dir and on the worktrees root's
   volume, the db file size (with its WAL), the worktree count.
5. **Runners by kind**: the harness rows (claude, codex, ollama and the rest) and whether each one's binary resolves.
   Most of this exists already for the runners page. Reuse it.

## Second wave

6. **Machine**: CPU% and memory used and total, and a 60-point CPU% series.
7. **Per runner**: CPU% and RSS per supervised runner pid, and summed per room.

Both need per-OS code (Windows `GetSystemTimes`, `GlobalMemoryStatusEx`, `GetProcessTimes`, `GetProcessMemoryInfo`,
Linux `/proc`, macOS `sysctl` and `ps`), with no new dependency, since the stack keeps to the standard library plus
`golang.org/x/sys` if it is already in `go.mod`.

## Notes for the builder

- One sampler goroutine owns the snapshot. A slow disk walk runs on its own slower timer and never blocks the 10s
  tick.
- The event is small. No per-card rows, which travel in `task` events (r-009).
- A room with no hub still serves both on its own address.
- Tests: the snapshot's shape, the push cadence with a fake clock, the push on an agent-count change, the GET equal to
  the last pushed snapshot, and a failing sampler that leaves the last good values with a `stale` mark rather than
  zeros.
