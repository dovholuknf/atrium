# r-019. A merged worker is culled without anybody remembering to

Status: BUILT 2026-09-29 on `claude/r-019` by @runtime, except the parts named below. Migration
`0075_work_merged_cull`.

Finished workers piled up on the board because directors forgot to cull them. The design is @rnd's:
`docs/rnd/merged-cull-design.md` (on `claude/rnd`, `e86abb7`). A git `post-merge` hook runs `atrium merged`, the room
marks finished workers the merge covered, and the sweep culls them at `cull_at` with every check re-run. A merge is
still not an acceptance: the grace period, a new turn and `hold` are the window to send the work back.

Built: `atrium merged`, the mark, the grace setting `merged_cull_grace`, the hold, the sweep, the cull archiving the
card and setting the work item `accepted` (the first code to do so), `atrium archive-workers`, the launch tag, the
`origin:agent` worker rule, the room's `POST /v1/merge-proof`, the `tip` a cull accepts, and
`scripts/install-git-hooks.ps1` (built, NOT run against any real repository).

Not built:

- Across rooms item 1 (`atrium_cull` resolving `name@room` and `room~id`) is @fabric's f-010.
- The hub calling `/v1/merge-proof` and sending `{into, tip}` to the owning room, and the hook marking a remote card
  through the hub, both wait on that routing. The room side is done and tested, and `atrium_cull` already takes `tip`.
- Item 3 (a room's 404 turned into "update the room") is @fabric's, and the chip is @ui's.
- A test of the HTTP routes themselves: their handlers are thin over daemon methods that are tested.
