# r-025. heldFor reports "line" for a hold that is not the line (bug)

Status: BUILT

The board said "clear the line to deliver" on a card whose line was empty. `heldFor` fell back to `HeldForLine` for
anything that was not a dialog or a turn, and the real hold was a new-context cycle.

Fixed in `internal/daemon/pendinginject.go`: new `HeldForNewContext = "new-context"`, checked first in the order
`attempt` checks. `HeldForLine` is answered only when `peerGateOpen` is false. With the gate open and nothing else
holding, the reason is empty (a waiting message with no reason named). The retry's final note uses `heldFor` too.
Tests in `heldfor_r025_test.go`.
