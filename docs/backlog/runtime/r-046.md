# r-046. claudeAuthCheck counts a sign-in token that every launch strips (bug)

Status: not started. Owned by @runtime. Found by the r-033 design worker, 2026-09-30, and @rnd asked for it filed and
fixed on its own (change 3 of the r-033 review).

`claudeAuthCheck` (`internal/runnersetup/claude.go`, around line 39) counts a `CLAUDE_CODE_OAUTH_TOKEN` in the daemon's
environment as claude being signed in. But `inheritedTaint` (`internal/daemon/launch.go`) strips every `CLAUDE_CODE_*`
name from a runner's environment at launch, so a runner never sees that token. The check says "signed in" for a claude
that a launch then starts signed out.

- The check answers from what a launched runner will actually have: a token atrium strips does not count.
- A test pins it: the token in the daemon env, and no other sign-in, reads as not signed in.
