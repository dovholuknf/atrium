# r-031. Machine CPU and memory on the room stats push (feature)

Status: BUILT 2026-09-30. Second wave of r-010 (`docs/backlog/runtime/r-010.md`), machine half. Per-runner `cpu_pct`
and `rss_bytes` are still not built.

## What

The room's stats snapshot gains a `machine` object, sampled on the existing 10 s tick and never stored:
`cpu_pct`, `cpu_series_pct`, `mem_used_bytes`, `mem_total_bytes`, `mem_series_pct`, `stale_since`.

- The series are 60 one-minute averages, oldest first, ending on the minute `tokens.series_end` names. A minute with
  no sample is JSON null, not 0, which would claim an idle machine.
- CPU is absent until the second sample. A failed sample keeps the last good values and gains `stale_since`.
  `machine` is absent until one sample succeeds.
- Windows: `GetSystemTimes` and `GlobalMemoryStatusEx`. Linux: `/proc/stat` and `/proc/meminfo` (total minus
  MemAvailable). macOS: sysctl only.

## macOS

CPU ticks need `host_statistics`, which is cgo, and there is no `kern.cp_time`. So on darwin `cpu_pct` and
`cpu_series_pct` are ABSENT, and load average is not substituted. Memory is `hw.memsize` minus free, external and
purgeable pages (`vm.page_free_count`, `vm.page_pageable_external_count`, `vm.page_purgeable_count`). It has only been
cross-vetted, never run on a Mac.
