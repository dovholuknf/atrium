# r-036. A directory-named hook matched by pid halts the store (bug)

Status: not started. Owned by @runtime. Found by @review's cr48 correctness review, HIGH, proven
(`docs/review/cr48-2d0ac78-ada747b.md`). Introduced by da682110 (r-021b).

`Register` with `NameSource == dir` (internal/store/tasks.go:186-195) looks the name up only among cards that are not
done and not archived. When that misses, the pid plus worktree fallback (198-205) can match a different, live card,
and `refreshObserved` (300-303) writes the name onto it. If a done card already holds the name, `UNIQUE (wire_name)`
refuses, the error is not transient (store.go:736), and `guard` halts the store (778-780). One session hook stops the
whole room until a restart.

Reached by an unbound hook (no `ATRIUM_TASK_ID`: a joined, external or older session) whose directory base name
(`hookAgent`, cli/join.go:91) matches a done card, in a checkout where a live card has the same pid and worktree.

Proof: `TestScratchDirNameOnPidMatchCollidesAndHalts` in
`D:/worktrees/claude/reviews/github-dovholuknf-atrium/cr48-2d0ac78-ada747b/daemon/scratch/internal/store/`, which
prints `store is halted: constraint failed: UNIQUE constraint failed: task.wire_name (2067)`.

The reviewer's suggestion: when the name is derived, do not let a pid fallback match rewrite `wire_name`, or run the
stale-name COUNT before the pid fallback and return `ErrStaleName` for a name any other card holds. Add the pid-match
case to resumeclaim_test.go, which has none.
