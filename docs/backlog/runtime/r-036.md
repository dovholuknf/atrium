# r-036. lockClaudeConfig fails on Windows instead of waiting (bug)Status: BUILT 2026-09-30 on `claude/r-036` by @runtime.`TestConcurrentClaudeWritesKeepEveryChange` failed under load with `mkdir ...\.claude.json.lock: Access is denied.`Cause: `lockClaudeConfig` took the lock with `os.Mkdir` and retried only on `os.ErrExist`. On Windows, Mkdir of adirectory another holder just removed, still pending delete, returns ERROR_ACCESS_DENIED, so the lock failed hardinstead of waiting. A real launch racing another launch's trust write would fail the same way.Fix: `lockBusy(err, goos)` is true for `os.ErrExist` everywhere and for a permission error on Windows only. The lockretries while busy until the existing `claudeLockWait`, then fails naming the real error. Linux and macOS stillfail on a permission error. Mkdir goes through the `lockMkdir` seam. No timeouts changed. No other lock in thepackage has this shape (jsonfile.go's Remove calls are temp-file cleanup).
