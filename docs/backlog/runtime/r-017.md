# r-017. A `health` event, so the board stops polling /v1/health (feature)

Status: BUILT 2026-09-29 on `claude/r-017` by @runtime. Asked for by @rnd's review of f-008 (hub events replacing the
board's polls, `docs/backlog/fabric/f-008.md`), passed on by @fabric. Room-side. @ui drops the board's health timer in
the same deploy as this event, not before.

The board reads `/v1/health` every 10 seconds only to learn `halted` (and its cause) and `settling`. Nothing emitted
those, and a storage halt keeps the human listener and the stream up, so the board never reconnected to find out.

- A `health` event, `{"halted", "cause", "settling"}` (`cause` only when halted), the same values `/v1/health`
  answers, without the build id.
- Published where each changes. `onHalt` publishes it beside the existing `halted` event. The settle window is worked
  out from a clock and a pending set, so nothing fires when it closes: `watchSettle`, started right after
  `settle.begin`, publishes `health` as the window opens and once more the moment it closes, then stops.
- The hub relays any room event, so nothing changes on the hub side. `/v1/health` stays for the first paint.

Tests: `TestAHaltIsPublishedAsHealth`, `TestTheSettleWindowOpeningAndClosingIsPublished`.
