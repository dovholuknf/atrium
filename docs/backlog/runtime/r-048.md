# r-048. Claim can succeed with the card left unnamed (bug)

Status: open. Owned by @runtime. Found by @review's cr2 correctness review: one MEDIUM (proven in the store) and two
LOWs (`docs/review/cr2-ada747b-2ce6443.md`). They are follow-ups to r-040. Still present at claude/landing 9429ac65.

1. **MEDIUM: Claim leaves the card unnamed** (store/tasks.go:321 and :371 on landing; intake.go:443).
   - When another row holds the name, r-040's guard in `refreshObservedAt` keeps the card's current name. For
     `Claim`, that name is empty, so the UPDATE writes NULL and `Claim` returns nil.
   - Its caller, daemon/launch.go:1019, treats nil as "named". Two launches of the same title, with no lock across
     `WireNameHeld` and `Claim`, can then start a runner whose `ATRIUM_AGENT_NAME` attaches to the other card through
     Register (launch.go:1164).
   - Fix: in `Claim`, refuse when the name was not taken: return an error when `t.WireName != obs.WireName` after
     `refreshObservedAt`. Or have the guard return a sentinel that `Claim` maps to a refusal, while Register and
     Observe keep the old name.
   - Test: Register a card named `taken`, Offer a second card, and Claim it as `taken`. `Claim` must error, or return
     the card named `taken`.
2. **LOW: a derived name never names an unnamed card found by pid** (tasks.go:225).
   - Apply `obs.WireName = task.WireName` only when `task.WireName != ""`.
   - Test: Offer a card, set its worktree, pid 4242 and running. Register with a free name derived from the
     directory, at the same worktree and pid. The same card must come back named.
3. **LOW: `WireNameHeld` has no store test, and `launchedName`'s doc is stale.**
   - Assert three cases: a done card's name is held, no card is not held, and a qualified name with a tenant set is
     held.
   - Rewrite daemon/launch.go:1368-1373. A done or archived card's name is no longer free, so a relaunch gets `-2`.
