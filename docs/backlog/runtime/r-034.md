# r-034. Standing rules can name MCP tools, and the importer stops skipping them (feature)

Status: not started. Owned by @runtime. From @rnd's gateway research (`docs/rnd/gateway-fit.md`, idea 1), passed on by
the orchestrator 2026-09-30. Design first, reviewed by @rnd before it is built. After r-029.

The permission gate already sees every `mcp__` tool call (`hook_permission.go`, `onPermRequest`), and `MatchRule`
matches `tool = ?` exactly, so a rule for an MCP tool would work. But the settings importer skips every `mcp__` entry
as "atrium does not gate" it (`internal/claudeconf/claudeconf.go` `toolsWeGate` and `convert`, asserted by
`claudeconf_test.go`). So every gateway call is asked of the human or waved through by auto mode.

- The importer brings `mcp__...` allow and deny entries in as rules.
- Settle first: `permSummary` for an MCP call falls through to compacted JSON, so a rule PATTERN would match JSON
  text. The design says what an MCP rule matches (the tool name alone, or a stable summary of its arguments).
- The permission chain's order is untouched.
