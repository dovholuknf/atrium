# r-040. A directory-named hook matched by pid halts the store (bug)

Status: BUILT on claude/r-040. Owned by @runtime. Found by @review's cr48 correctness review, HIGH, proven
(`docs/review/cr48-2d0ac78-ada747b.md`). Introduced by da682110 (r-021b).

`Register` with `NameSource == dir` looked the name up only among cards that are not done and not archived. When that
missed, the pid plus worktree fallback could match a different, live card, and `refreshObserved` wrote the name onto
it. A done card already held the name, `UNIQUE (wire_name)` refused, and `guard` halted the store.

Fixed two ways. `Register` keeps the matched card's own name when the card was found by pid and the name is a guess
from the directory. `refreshObserved` checks, in the same guarded op, that no other row holds a name before writing
it, and otherwise keeps the current name and logs both cards, so no caller can reach the constraint. `create` cannot
be reached with a held name: a told name matches any status and a derived name meets the stale COUNT. Tests in
`internal/store/registername_test.go` failed with the halt before the fix.
