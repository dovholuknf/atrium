# r-033. A runner's environment is an allowlist per harness, off by default (security, HIGH)

Status: not started. Owned by @runtime. From @rnd's gateway research (`docs/rnd/gateway-fit.md`, idea 4), passed on by
the orchestrator 2026-09-30. Design first, reviewed by @rnd before it is built. After r-029.

Every runner inherits the daemon's whole environment minus a deny list (`childEnvFrom`, `internal/daemon/launch.go`).
So `CLAUDE_GH_TOKEN` and `BB_TOKEN` reach every worker, including a lean one writing a docs change.

- A per-harness environment allowlist: the names a runner row passes on, like mcp-gateway's `env_policy: closed`.
  The OS basics every process needs (PATH, HOME or USERPROFILE, SYSTEMROOT, TEMP and the like) are always kept.
- Ships with the DEFAULT UNCHANGED: everything passes, as now. A setting turns enforcement on, because workers that
  use `gh` would break. clint flips it.
- The design lists which runners need which token (for example @review's `gh` use needs `CLAUDE_GH_TOKEN`).
- A launch's own `env` field keeps working, and is shown by name only, as now.
