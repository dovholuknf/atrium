# r-038. Scheduled launches: a row like a source, with a schedule and a launch request (feature)

Status: designed 2026-09-30 in `docs/rnd/scheduled-launches-design.md` (@rnd), build later. Schedules live on the
hub, and the nightly test suite (Go for @merge, UI for @ui) is the first use. Owned by @runtime. Filed 2026-09-30 for @rnd from `docs/rnd/competitor-features.md`
(item 4, claude/rd-002 61eb32b5). Not built.

A source (`internal/store/sources.go`, `internal/daemon/sources.go`) is a command on a timer whose output becomes inbox
items. A scheduled launch is the same row shape, with a schedule and a LAUNCH REQUEST in place of the command, so
"every weekday at 07:00, start a worker in this directory with this brief" needs no external cron.

- The row: schedule, a stored LaunchRequest (harness, cwd, prompt, brief, model, effort, lean, tags), enabled, and
  last run and last result, as a source has.
- The source rules carry over: a run that fails is reported on its own row and retried on its next tick, and three
  consecutive failures switch it off with the reason attached. A schedule is a suggestion, never durable state.
- Open for the design: overlap (a previous run's card still running), the launch cap, missed runs across a restart,
  and a schema change, as a new migration at the END of the slice.
