# r-013. Coalesce "task" events per card, so a burst does not run three queries per card per publish (follow-up)

Status: BUILT (branch claude/r-013). Filed 2026-09-29 from @rnd's review of r-009 (a "should", not a blocker). Owned by @runtime.
Room-side. Built: PublishTask marks the card and a 200 ms timer per card sends the row read at send time.

r-009 made every "task" event the full `/v1/tasks` row, so `PublishTask` runs three queries (`RepliesOwedFor`,
`OpenAskCount`, `GetSeen`) synchronously in every caller, about 40 call sites. None is on the per-tool-call path. But
bursts happen: a restart wake publishes every card, and a say fan-out publishes many.

Fix: coalesce per card. Publishing a card that already has an event pending within 200 ms does nothing, and the send
reads the row at send time, so the board's upsert stays exact and the queries are bounded to one row per card per
200 ms. Tests: ten publishes of one card inside the window send one event carrying the latest state, and two cards
each get their own.
