# r-039. An agent reports its own resume command, so a runner without built-in resume comes back (feature)

Status: design only, clint ranks. Owned by @runtime. Filed 2026-09-30 for @rnd from `docs/rnd/competitor-features.md`
(item 5, claude/rd-002 61eb32b5). Not built.

Claude has a resume id atrium stores and restarts with. A runner that has no built-in resume comes back after a
restart as a fresh session that has lost its place. Let the agent itself tell atrium the command that resumes it, and
use that on the restart.

- Pacing already exists (`reopen.go`, `reopenGap`), so this is only the self-reported command.
- A command a model wrote is a command atrium runs. The design has to bound it: only the card's own runner binary,
  args only, never a shell string, shown on the card, and overridable by a human.
- How it is reported (an `atrium` subcommand, like `atrium finish`, since a command is the channel every runner has),
  and where it is stored (the card, beside the resume id).
