# r-042. cr48 lows in store, daemon and cli (bug)

Status: BUILT on claude/r-042. Owned by @runtime. The LOW findings of @review's cr48 correctness review, grouped. Each is
written up in `docs/review/cr48-2d0ac78-ada747b.md` and in the slice files of the run folder
`D:/worktrees/claude/reviews/github-dovholuknf-atrium/cr48-2d0ac78-ada747b`.

- `ClaimResumeID` (store/tasks.go:830-878) is not one transaction: a retry after the clear loses `Moved` (unproven),
  a missing claimant clears the holder and reports `Stored: true` (proven), and nothing enforces one holder per
  conversation (unproven).
- resumeclaim_test.go:66 tests only the done half of "finished or archived", and nothing tests the pid-match case.
- daemon/supervisor.go:2172 clears a bad resume id with `SetResumeID(id, "")`, which is a no-op (tasks.go:797). Older
  than the range (048bc7cb).
- daemon/replies.go:63 answers "no such card" for any store error, and line 79 falls back silently.
- daemon/replies_test.go: tail seek, cache invalidation, multibyte cuts, bad timestamps and the unsupervised
  `ownsSession` branch are untested.
- Names are derived three ways (`hookAgent`, cli/hook.go:402-408, `agentName`), and `/permission` and `/activity`
  send no `name_source`.
- cli/ancestry_windows.go:59 has no argv[0] fallback for a version-named claude (unproven that one exists).
- cli/hook.go:156 walks the process table before deciding the hook has nothing to do.

## What was done

1. ClaimResumeID is one transaction. A missing claimant clears nothing and reports Stored false. A unique index is not
   needed: the transaction clears every other holder before it sets this one, and every writer of resume_id but
   SetResumeID goes through it. SetResumeID alone can still write an id another card holds, which a unique index
   would forbid, so an index is worth a later look if that path is ever used for adoption.
2. Tests for the archived half of the stale-name rule and the pid-match case.
3. Store.ClearResumeID added and used by the supervisor.
4. repliesFor answers no such card only for sql.ErrNoRows. The screen fallback logs once per transcript.
5. Tests for the tail seek, cache invalidation, rune-boundary cuts, bad timestamps and the unsupervised ownsSession.
6. One name function, hookAgent, used by join, /permission and the activity hook. /permission and /activity now send
   name_source, and the daemon reads it (permission passes it to Register). A missing one is read as before. One
   consequence: a gated call from a directory-named session no longer matches a finished card.
8. The permission hook finds the runner pid only after the gate, payload and tool checks pass.

## Skipped

7. ancestry_windows.go: no change. The Linux and macOS fallback exists because the native install is a file named for
   its version, but nothing in the code shows a Windows install is, and reading another process's argv[0] on Windows
   means reading its PEB, which is too heavy for the hot path without proof it is needed.
