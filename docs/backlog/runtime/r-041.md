# r-041. A nested claude's end, Stop and permission hooks still land on the parent card (bug)

Status: not started. Owned by @runtime. Found by @review's cr48 correctness review, MEDIUM, three findings with one
cause (`docs/review/cr48-2d0ac78-ada747b.md`). Follows r-021, which closed the SessionStart door only.

A `claude -p` run from a session's Bash tool inherits `ATRIUM_TASK_ID` and `ATRIUM_AGENT_NAME`, so its hooks name
the parent card. `ownsSession` is asked only on session start.

- End and compact (internal/daemon/session.go:171-176, 242-253): the resume claim and `Observe` run for every event.
  A nested end replaces the parent's resume id, writes the nested pid, and ends the parent card. Proven:
  `TestScratchNestedEndMovesResumeAndEndsParent`.
- Stop (internal/daemon/messages.go:231-317): the resume id is refused, but `refreshObserved` writes pid 0 (proven,
  `TestScratchNestedStopZeroesPid`), and `turnEnded`, the silent-stop check and `takeMessages` still run (from
  reading), so a message queued for the parent can be delivered to the nested session and lost.
- Permission (internal/cli/hook_permission.go:102, daemon.go:708-716, store/tasks.go:293-303): the nested pid
  overwrites the parent's (proven, `TestScratchNestedPermissionOverwritesParentPID`, 100 becomes 200). On an
  unsupervised card the reaper can then file the parent dead. Live today through `atrium-perm-hook.ps1`, which sends
  the same fields.

The cli half: the Stop and activity hooks send no pid (turn.go:224, hook.go:413) and the permission hook sends no
task id, so the daemon has nothing to check. The run folder is
`D:/worktrees/claude/reviews/github-dovholuknf-atrium/cr48-2d0ac78-ada747b`.
