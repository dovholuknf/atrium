# r-041. A nested claude's end, Stop and permission hooks land on the parent card (bug)

Status: BUILT. Owned by @runtime. Found by @review's cr48 correctness review (`docs/review/cr48-2d0ac78-ada747b.md`),
MEDIUM, three findings with one cause. Follows r-021, which closed the SessionStart door only.

The daemon now asks `ownsSession` on every bound report, not only a session start:

- Session end, compact, join and leave (`session.go`): a report whose pid is not the card's runner is dropped whole
  and answered ok. An operator's `atrium join` or `leave` sends no task id and no pid, so it is never bound and never
  gated.
- Stop (`messages.go`): dropped before any turn-end work, so it never takes the parent's queued messages. The Stop
  hook (`turn.go`) now sends `runnerPID()`.
- Permission (`daemon.go`): still answered through the whole chain in the same order, but a pid that is not the
  card's runner is not written to the card.
- The activity hook is unchanged. It moves no stored state, and it is the hot path, so it gets no process walk.
- A hook that sends no pid (pid 0) is believed, as before.

Not covered: the permission hook sends no task id, so the card is found by wire name, and a nested session under a
different name is a different card anyway.
