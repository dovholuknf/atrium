# r-018. POST /v1/preflight, and `atrium requirements <file> --json`

Status: built on claude/r-018, awaiting merge. Approved by the orchestrator 2026-09-29. Owned by @runtime. Room-side.

What: the room answers, from inside its own process, which tools it can run, whether a runner is signed in, and which
environment names are set. The binary is also the one parser of `atrium.requirements.yaml`.

Why: ssh sees a different PATH from the room, so measuring from ssh is a guess (`docs/fabric/room-requirements-design.md`
section 4). One parser means one set of schema errors for `scripts/room-check.ps1`.

Where: `internal/daemon/preflight.go` (route on the human listener only), `internal/requirements/`,
`internal/cli/requirements.go`, `--started-by` in `internal/cli/roomrun.go` and `cli.go`.

## Shapes for `scripts/room-check.ps1`

`atrium requirements <file> --json` prints one object, exit 0. Always present: `version` (number, 1), `toolchain`
(name to `{from?, min?, windows?, os?[]}`, `min` kept as text), `runners` (name to `{hooks?, gate?, mcp?[],
helpers?[], smoke: bool}`), `room` (`{survives: none|logoff|reboot, runner_auth: []}`), `env` (NAME to
`{required: bool, value?: string}`), `services` (`[]string`). Only when given: `atrium` (`{min}`, a hex sha) and
`git` (`{base, mirror, clone, worktrees, fresh}`, templates unresolved, defaults hub-main,
`{home}/git/github/{owner}/{repo}`, `{clone}-worktrees`, false).

A refusal prints one stderr line per problem, in file order, nothing on stdout, and exits 1:
`atrium.requirements.yaml:LINE: dotted.key.path: reason`. An absolute path says `"<value>" is an absolute path. the
file describes a project and is read on machines that are not this one, so use {home}, {owner}, {repo} or {clone}`.
A secret-looking value says `looks like a secret. the file names what a room needs and never carries a credential.
name the variable under env and set it on the room`. A plain value on a secret-named env var says `<NAME> reads as a
secret, so it cannot have a value in this file`. An unknown key says `unknown key. known keys here: ...`. A missing
file or a YAML syntax error also exits 1.

`POST /v1/preflight` answers 200 `{"tools": {k: {ok, path, output, error}}, "runner_auth": {k: {...}},
"env_present": {NAME: bool}, "pid": n, "started_by": ""}`. `error` is `""`, `not found`, `timeout`,
`unknown key, resolved at <path>` or the exit error. Maps are always present. Output is capped at 4096 bytes. A
non-JSON body or a list over 64 keys answers 400.

Left over:
- `--started-by` is not passed to a detached start or a restart, on purpose. A supervisor that restarts through
  `atrium room --detach` will lose the marker. That is @fabric's registration to settle.
- The hub's fan-out allowlist (`internal/link/fanout.go`) does not list `/v1/preflight`. Reaching a room through the
  hub is a separate step.
- `atrium.requirements.yaml` at the repo root (build order item 8) is not committed here.
