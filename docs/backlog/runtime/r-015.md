# r-015. The usage tab's room side: grouping by department and director, limit readings, and backfill (feature)

Status: approved by clint 2026-09-29 with the whole usage-tab design (`docs/rnd/usage-tab-design.md`, d8f0e5b on
claude/rnd, sections 3.3.2, 3.4, 3.5 and 3.7). Owned by @runtime. @ui builds the board side. Field names
AGREED with @ui 2026-09-29, and @ui builds against mocks of exactly these, so a name change is sent to it.
Room-side. The calls fix (section 3.1) is r-012, already built. Building on sg3 as r-015.

## 1. Grouping by department and by director (design 3.4)

A worker is culled and its card pruned, and its tags and launcher go with it, so a rollup from today's card list would
file last week's spend under "no department". So the row keeps them from the time of the turn.

- `session_usage` gains `dept`, `launcher` and `launcher_id`, all `TEXT` with NO default, so rows from before the
  migration read NULL. One migration at the END of `schema.go`'s slice, tolerant of already being there. It is after
  r-007's `0071` and r-014's `0072`, so it is numbered at build time.
- Written when the row is written (`internal/daemon/usage.go`): `dept` is the card's `dept:<x>` tag value, "" when
  none. `launcher` is the alias, else the handle, of the card the row rolls up under for "director": the card itself
  when tagged `atrium:director`, else its launcher, "" when the operator started it. `launcher_id` is that card's id.
- `GET /v1/usage?group=dept|launcher` adds `groups: { "<key>": UsageSums }` to each bucket, beside `total`, `cards`
  and `causes`. Key "" is "no department" or "clint". Key `@before` holds rows from before the columns existed. With no
  `group`, the answer is unchanged.

## 2. Room-kept limit readings (design 3.3.2, clint: yes, at no token cost)

The flameout projection fits a line through the 5h and weekly percentages the cards' statuslines report. So a
reload, a second browser or the phone draws the same projection, the room keeps the readings. Nothing is asked of a
model: a reading is a number the statusline already reports.

- A table `limit_reading` (at the END of the migration slice, `CREATE TABLE IF NOT EXISTS`): `task_id`, `kind`
  (`five_hour` or `weekly`), `pct`, `resets_at`, `at`. A row is written in the telemetry path
  (`internal/daemon/telemetry.go`) only when a card's reported pct or reset differs from the last row for that card
  and kind, so an unchanged statusline writes nothing.
- Kept 8 hours for `five_hour` and 7 days for `weekly`, pruned on the sweep timer (`sweep.go`), never on the
  telemetry path.
- `GET /v1/usage/limits?since=<RFC3339>` on the human listener answers
  `{ "readings": [ { "at", "card", "kind", "pct", "resets_at" } ] }`, for the first paint. New readings arrive on the
  telemetry updates the board already gets, so there is no new event and no polling. The room computes no fit.

## 2b. Tokens per accepted item (design 3.5, rank 6), wanted by @ui

The cost of each work-ledger item that reached `accepted`, from the counted tokens of every card linked to it in
`work_log`. If the board would rather not join the ledger itself, `GET /v1/usage/items?since=` answers per item:
`item`, `title`, `counted`, `cache_read`, `cards`, `split` (the number of items the card's cost was divided across,
since a card linked to two items is split evenly), plus `unlinked`, the count of accepted items with no card on
record.

## 3. Backfill from transcripts (design 3.7)

- `atrium usage backfill [--since 30d]`, a one-time CLI command, never a timer. It reads the transcripts of the room's
  cards' known resume ids, and writes `session_usage` rows with cause `backfill` for turns not already recorded (no
  double count), stopping at `UsageMaxBack`. `dept` and `launcher` are filled from the card as it is now, since that is
  all there is, and the command says so.

## Tests

- A row written for a worker carries its dept and its director. A director's own row rolls up under itself. An
  operator's card rolls up under "".
- Rows from before the migration land in the `@before` group, never in a department.
- `?group=dept` sums per group equal the rows. No `group` answers exactly as before.
- Readings: a row only when pct or reset changes, pruned past 8 hours (five_hour) and 7 days (weekly), served by since.
- Backfill: a transcript's turns become rows once. Running it twice adds nothing. It stops at `UsageMaxBack`.
