# r-015. The usage tab's room side: grouping by department and director, limit readings, and backfill

Approved by clint 2026-09-29 with the whole usage-tab design (`docs/rnd/usage-tab-design.md`, sections 3.3.2, 3.4,
3.5 and 3.7). Field names agreed with @ui. Room-side, so it waits on clint's restart.

Status: parts 1, 2 and 2b BUILT. Part 4 not yet.

## 1. Grouping by department and by director (design 3.4). BUILT

A worker is culled and its card pruned, and its tags and launcher go with it, so a rollup from today's card list would
file last week's spend under "no department". So the row keeps them from the time of the turn.

- `session_usage` gains `dept`, `launcher` and `launcher_id`, all `TEXT` with NO default, so rows from before the
  migration read NULL. Migration `0073_usage_grouping`.
- Written when the row is written (`internal/daemon/usage.go`, `stamp`): `dept` is the card's `dept:<x>` tag value, ""
  when none. `launcher` is the alias, else the handle, of the card the row rolls up under for "director": the card
  itself when tagged `atrium:director`, else its launcher, "" when the operator started it. `launcher_id` is that
  card's id.
- `GET /v1/usage?group=dept|launcher` adds `groups: { "<key>": UsageSums }` to each bucket, beside `total`, `cards`
  and `causes`. Key "" is "no department" or "clint". Key `@before` holds rows from before the columns existed (NULL).
  With no `group`, the answer is unchanged.

## 2. Room-kept limit readings (design 3.3.2, clint: yes, at no token cost) BUILT

- A table `limit_reading` (at the END of the migration slice, `CREATE TABLE IF NOT EXISTS`): `task_id`, `kind`
  (`five_hour` or `weekly`), `pct`, `resets_at`, `at`. A row is written in the telemetry path only when a card's
  reported pct or reset differs from the last row for that card and kind, so an unchanged statusline writes nothing.
- Kept 8 hours for `five_hour` and 7 days for `weekly`, pruned on the sweep timer, never on the telemetry path.
- `GET /v1/usage/limits?since=<RFC3339>` on the human listener answers
  `{ "readings": [ { "at", "card", "kind", "pct", "resets_at" } ] }`, for the first paint. New readings arrive on the
  telemetry updates the board already gets, so there is no new event and no polling. The room computes no fit.

## 2b. Tokens per accepted item (design 3.5) BUILT

The cost of each work-ledger item that reached `accepted` in the range, from the counted tokens of every card linked
to it in `work_log`. `GET /v1/usage/items?since=` answers `{ "items": [ { "item", "title", "counted", "cache_read",
"cards", "split" } ], "unlinked": N }`. `cards` is how many cards are linked to the item. `split` is the number of items
the card's cost was divided across (a card linked to two items is split evenly). `unlinked` is the count of accepted
items with no card on record. Counted is input + output + cache writes (5m and 1h), and cache_read is apart.

## 3. Backfill from transcripts (design 3.7)

- `atrium usage backfill [--since 30d]`, a one-time CLI command, never a timer. It reads the transcripts of the room's
  cards' known resume ids, and writes `session_usage` rows with cause `backfill` for turns not already recorded (no
  double count), stopping at `UsageMaxBack`. `dept` and `launcher` are filled from the card as it is now, since that is
  all there is, and the command says so.

## Tests

- A row written for a worker carries its dept and its director. A director's own row rolls up under itself. An
  operator's card rolls up under "".
- Rows from before the migration land in the `@before` group, never in a department.
- `?group=dept` sums per group equal the rows. No `group` answers exactly as before.
- Readings: a row only when pct or reset changes, pruned past 8 hours (five_hour) and 7 days (weekly), served by since.
- Items: counted and cache_read per item equal the linked cards' rows, a two-item card is split evenly, unlinked counts.
- Backfill: a transcript's turns become rows once. Running it twice adds nothing. It stops at `UsageMaxBack`.

## Built notes

- 2b: a work item is keyed by its worker card, and `work_log` rows carry that same id, so `work_log` alone links no
  other card. The linked cards of an item are its own card and every card it continues (`work_item.continues`, walked
  back), since a relaunched worker is a new card on the same work. A card shared by two accepted items in the range is
  split evenly (integer division). `unlinked` is accepted items where none of those cards has a usage row.
