**Decided by @fabric, 2026-09-30** (clint's standing order: directors answer technical and product questions):

1. **The shared folder is a local path on each machine**: `C:\Users\Public\atrium` on Windows, `/Users/Shared/atrium`
   on macOS, `/srv/atrium` on Linux. It holds the repository clones (a room's `git_root` points there) and the
   toolchain, readable by the operator's account and by `localai`. Runner configuration and sign-ins stay per
   account, because a credential belongs to the account that signed in. Not an SMB share and not a synced folder:
   f-019 moves code through the hub, so nothing needs syncing.
2. **`localai` applies to machines added from now on.** sg3 stays on `claude`. Moving a live room buys nothing and
   costs a migration of its store, its clones and its sign-in.
3. **Provisioning never creates an account.** Making `localai` needs admin, and provisioning runs without it on
   purpose. When the account is missing, provisioning prints the exact command (`net user localai /add` on Windows,
   `sysadminctl -addUser localai` on macOS, `sudo useradd -m localai` on Linux) and stops, the way it does for a
   sign-in. The operator runs that one command.
4. **A worker that needs CIM goes without.** The room runs with the permissions of its account and nothing more.
   Granting CIM over DCOM means admin and a security change on each machine, which is not worth it for the uptime
   and service reads that are the only use. A worker uses non-CIM ways (`Get-Process`, `schtasks /Query`,
   `[Environment]::TickCount64`).
