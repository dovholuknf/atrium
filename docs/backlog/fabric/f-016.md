# f-016: `ancestry_darwin.go`, so `atrium session` finds the runner's pid on macOS

Status: DONE, in claude/main (`e0e650fc`).

`ancestry_other.go` walked to the runner through `/proc`, which macOS does not have. On a mac `runnerPID()` was
always 0, so every mac session lost the reconnect hint and the reaper's liveness. Found in `f-006`, landed on its own
at @rnd's request.

## Built

- `internal/cli/ancestry_darwin.go`: the same walk as the other platforms, reading name and parent from
  `kern.proc.pid` via `unix.SysctlKinfoProc`.
- The native claude install is a file named for its version, so `P_comm` is `2.1.285`. When the name does not match,
  argv[0] is read from `kern.procargs2` and matched instead.
- `runnerNames` and `maxHops` moved to `ancestry.go`, untagged, so the platforms cannot drift.
  `ancestry_other.go` is now `!windows && !darwin`.
- Darwin tests, including one that only runs under a runner (`ATRIUM_EXPECT_RUNNER=1`). Proven on m1mini under a
  real `claude -p`: it found the claude pid.
