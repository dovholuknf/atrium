## The item

The gate every room runs today is the dotfiles script `~/.claude/hooks/atrium-perm-hook.ps1`. f-009 copies it to each
remote room with `scripts/room-gate.ps1`. That works, and it costs three things:

- **pwsh on every room.** macOS and Linux rooms need pwsh for this one script and nothing else. The brief for item 1
  says the remote side must not need pwsh on mac or linux, and the gate is now the only thing that does.
- **A snapshot, not a version.** Each room holds whatever the dotfiles copy was on the day `room-gate.ps1` ran. The
  wire contract lives in `internal/daemon/permwait.go` and the script lives in another repo.
- **pid 0 on macOS.** The script walks ancestors with `Get-CimInstance`, which macOS does not have, so a mac room's
  permission rows carry no pid and liveness is never checked (seen on m1mini in f-009).

Proposed: `atrium hook --event permission`, a Go subcommand in the binary every room already has, registered first in
PreToolUse by `/v1/hooks/install` and by provisioning. Then `room-gate.ps1` and the copied script go away.

## What it has to keep, from the script

The contract is `permwait.go`'s header. Nothing there changes. The subcommand does what the script does, in order:

1. `ATRIUM_PERM_GATE`: `off` exits 0. `on|force|1|true|yes` forces the gate. Unset means "gate if joined or wired".
2. Agent name: `ATRIUM_AGENT_NAME`, else the leaf of cwd. The same rule `atrium join` uses.
3. **The probe.** `GET /gate?agent=<name>` with a 3s deadline (`ATRIUM_PERM_PROBE_TIMEOUT`). No answer means fail open.
   This is what keeps one frozen room from holding every gated call on the machine, because the POST has no deadline.
4. Wired check: an `.mcp.json` naming `atrium-agent` up the tree (Mode A). Keep it, it is cheap.
5. Skip list: Read, Grep, Glob, WebFetch, WebSearch, TodoWrite, Task, ToolSearch.
6. The command summary per tool shape (command, file_path with the edit or write note, url, pattern, else compact JSON)
   and `details`.
7. `POST /permission` with agent, command, tool, pid, cwd, details, dedup_key. No deadline unless
   `ATRIUM_PERM_TIMEOUT`.
8. Output: `hookSpecificOutput` with `permissionDecision` allow or deny and the reason, and `updatedInput` when the
   human edited the command.
9. **Any failure exits 0 with no output**, which is fail open. A hook must never fail a session.

## What it does better

- **`tool_use_id`.** The script sends only a hash as `dedup_key`. The payload carries `tool_use_id` and the daemon
  already prefers it (`permwait.go`, `ToolUseID`), so the replay window stops applying. Free, once it is Go.
- **A real pid everywhere.** `runnerPID()` in `internal/cli/ancestry_*.go` is already shared with `atrium session`.
  BUT `ancestry_other.go` reads `/proc`, which macOS does not have either, so `atrium session` also reports pid 0 on
  mac today. f-006 needs an `ancestry_darwin.go` (`sysctl kern.proc.pid`, via `golang.org/x/sys/unix`), and that fixes
  the session hook on mac at the same time. This is a finding in its own right and could land first.
- **Same binary as the other ten hooks**, so `whichexe.go` decides where it points and the board's hook panel can
  report it as installed or drifted like any other.

## Open, for @rnd

1. **"Install all" or not.** Every other hook only reports. This one blocks a tool call until a human answers, which
   is closer to `Stop` (optional, never swept in) than to the rest. My lean: it IS in "install all", because a room
   without it is a room whose work never reaches the board as a question, and board-wide auto mode is the answer to
   "I do not want to be asked". But it is shown with a warn line like `Stop`.
2. **Coexisting with the dotfiles script on this machine.** sg4's settings.json has the script registered, and clint's
   dotfiles install it. Two gates would ask twice. Options: `InstallOnly` treats a row running
   `atrium-perm-hook.ps1` as the permission hook and replaces it (the same rule already used for
   `atrium-session-hook.ps1`), or the Go gate is not installed where the script is. My lean: replace, and tell
   @dotfiles so the dotfiles installer stops writing it once atrium has its own. That is clint's machine, so it is
   asked, not done.
3. **Codex.** Codex has PreToolUse too, with `tool_use_id`. The subcommand can read either payload. Whether codex rooms
   get it registered is a `claudeconf` Target question (codex's `Wanted` list) and waits on whoever owns codex hooks.
4. **Ordering.** f-009 registers the script first in PreToolUse. Claude Code runs matching hooks in parallel, so
   first may not mean anything to it, and `InstallOnly` appends today. Worth one check on a real session before
   anybody builds a "first" placement: does the `tool-start` badge show while a call is still waiting on a human, and
   does that matter.
