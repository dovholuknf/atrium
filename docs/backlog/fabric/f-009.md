# f-009: the permission gate on remote rooms, and in provisioning

## The item

sg3 and m1mini had atrium's 10 hooks and no gate, so a worker's tool calls there never reached the board as permission
prompts. clint approved 2026-09-29: copy the one dotfiles script to each room, register it first in PreToolUse, and fold
it into provisioning.

## Done

- `scripts/room-gate.ps1 <room> [-Target] [-Check]`: steps source, pwsh, copy, register, reach, runner. Exit codes in
  its header. The settings edit is done on the operator's side and put back with scp, with a timestamped backup.
- `provision-room.ps1` calls it once after the hooks step.
- Installed on sg3 and m1mini, and smoked with a card on each (see the report on the card).

## Left

- f-006: atrium ships its own gate subcommand. This script and the dotfiles copy go away then.
- The gate's runner-pid walk uses `Get-CimInstance`, so on macOS the pid is 0 and liveness is not checked.
- Each new machine's copy is a snapshot of the dotfiles script. A dotfiles change reaches a room on the next
  `room-gate.ps1` run (the hash differs).
