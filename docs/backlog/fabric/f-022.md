# f-022: the hub's certificate proves a room's name on every transport (decision 18)

Status: built on `claude/f-022`, not merged, not deployed. Design was @rnd's `docs/rnd/overlay-room-identity.md`,
reviewed by @fabric 2026-09-30.
Owned by @fabric. Taken after f-020 and f-021, in section 6's order.

**Condition (atrium-87300, 2026-09-30): no existing room loses its link.** The new path ships ALONGSIDE the old one.
A room on today's overlay join keeps attaching as it does now, and the switch to certificate-only (refusing the old
join) is a step clint takes, never a deploy.

Run `direct.go`'s mutual TLS inside every overlay. The overlay decides only who may reach the hub, and the certificate
the hub signed names the room, on direct, OpenZiti and zrok alike. `ZitiAuthenticated` and `ZrokAuthenticated` go.
OpenZiti's `SourceIdentifier()` is a client-set label, not a proof (the design, section 2). Build order is the
design's section 6. Added in review:

1. Wrap only the room-link listener. The board served over zrok or ziti has no client certificate and must never be
   wrapped. Test it.
2. Every connection kind rides the wrapped dial, including f-019's `git` kind.
3. The ziti edge conn must honour `SetDeadline`, which the handshake and `hearHello` rely on. Check before rollout.
4. `provision-room.ps1`'s ziti and zrok joins mint the new join string (secret and CA pin) and refuse the old form
   with the re-join sentence.
5. Confirm from the hub's room list which rooms use an overlay link. sg3 and m1mini attach direct.

## Built (f-022 worker)

- `link.MixedListener` peeks one byte of each accepted connection. `0x16` is wrapped in `tls.Server` with direct's
  config, so the certificate names the room. Anything else is a legacy connection, kept as it was. Only the room-link
  listener built in `openHub` is wrapped, and a source-scan test pins that (the board's own overlay listener cannot be
  run without a real ziti or zrok, so it is proven by that scan and nothing more).
- Setting `overlay_legacy` (`allow` default, `refuse`), read per connection with no restart, a read error allows.
  `atrium rooms legacy [allow|refuse]` flips it and nudges the hub. Never flipped automatically.
- An unproven attach writes a `room-unproven` audit line and `Attached.Proven` is false in the rooms list. The startup
  warning stays while the old path is allowed and counts the unproven rooms.
- Room side: `link.Proven` wraps every connection kind in `tls.Client` inside the Dialer. A room wraps only when its
  saved join is the new form AND room.crt exists, so an old-form join never wraps, whatever is in the keys directory.
  A new-form join enrols over the overlay (`EnrolOver`), spending the secret once, and `rooms token` mints that form.
- Deadlines: ziti `edge.Conn` and zrok's connection are the same type, and `SetDeadline` is implemented for real
  (sdk-golang v1.2.8, `ziti/edge/network/conn.go`).
- Not done: `provision-room.ps1` (its own item, review point 4), and the flip of `overlay_legacy` on the real hub.
- One flaky test seen once, `TestARoomWithNoCardsAnnouncesAnEmptyList`, timed out and passed on the full rerun.
