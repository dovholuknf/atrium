# f-022: the hub's certificate proves a room's name on every transport (decision 18)

Status: design accepted (@rnd's `docs/rnd/overlay-room-identity.md`, reviewed by @fabric 2026-09-30), not started.
Owned by @fabric. Taken after f-020 and f-021, in section 6's order.

**Condition (atrium-87300, 2026-09-30): no existing room loses its link.** The new path ships ALONGSIDE the old one.
A room on today's overlay join keeps attaching as it does now, and the switch to certificate-only (refusing the old
join) is a step clint takes, never a deploy.

Run `direct.go`'s mutual TLS inside every overlay. The overlay decides only who may reach the hub, and the certificate
the hub signed names the room, on direct, OpenZiti and zrok alike. `ZitiAuthenticated` and `ZrokAuthenticated` go.
OpenZiti's `SourceIdentifier()` is a client-set label, not a proof (the design, section 2). Build order is the
design's section 6. Added in review:

1. Wrap only the room-link listener. The board served over zrok or ziti has no client certificate and must never be
   wrapped. Test it.
2. Every connection kind rides the wrapped dial, including f-019's `git` kind.
3. The ziti edge conn must honour `SetDeadline`, which the handshake and `hearHello` rely on. Check before rollout.
4. `provision-room.ps1`'s ziti and zrok joins mint the new join string (secret and CA pin) and refuse the old form
   with the re-join sentence.
5. Confirm from the hub's room list which rooms use an overlay link. sg3 and m1mini attach direct.
