# f-024. Should setting the hub's notify command be loopback only? (bug, a question)

Status: not started, needs a decision. Owned by @fabric. Found by @review's cr48 correctness review, MEDIUM,
reachability proven, exposure not (`docs/review/cr48-2d0ac78-ada747b.md`).

`PUT /_hub/notify` stores an argv the hub executes, and `POST /_hub/notify/test` runs it at once
(internal/link/notifyapi.go:57, routed with no caller check at proxy.go:1278-1279). `serveControl` (1218) and
`serveNudge` (1243) refuse anything but `loopbackRemote`. A scratch test got 200 on both from 203.0.113.7. `/test` is
a bare POST, so it is also a simple cross-origin request, and each call starts another process.

The question: should PUT and `/test` take the same loopback gate as `/_hub/mcp`, or is a board share trusted to pick a
program the hub host runs, and if so, where is that said?
