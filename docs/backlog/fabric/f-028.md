# f-028. The control audit line carries caller text whole (bug)

Status: fixed, awaiting review. Owned by @fabric. Found by @review's cr2 correctness review: a MEDIUM, proven
(`docs/review/cr2-ada747b-2ce6443.md`). Still present at claude/landing 9429ac65. Introduced by ba732202.

**The rule.** ctlaudit.go's header says a describe function never writes a payload.

**What the code does.**
- Several describers write caller strings: `describeAlias` (`in.Alias`), `describeCull` (`in.Into`),
  `describeLaunch` (`in.Room`, `in.Runner`), and `describeSay` and `describeExit` (`in.To`, `in.Card`).
- Only the outcome is bounded, by `auditErrMax`. `RecordAudit` and `hubstore.Store.Log` store the detail as given.

**The result.**
- A loopback caller can write a row of any size.
- A newline in the text lets it forge a second line, for example `by orchestrator@sg3 (claimed): cull X, ok`.
- The row is written even when the call was refused.

**Fix.** In `auditDetail` (ctlaudit.go:66), strip control characters from `what` and cut it to a fixed rune bound,
as `auditOutcome` does.

**Test.** `describeAlias` with a 1 MiB alias plus `\n` must give a bounded `what` with no CR or LF. Repeat it for
each describer.
