# f-027. Launch caps: case-duplicate room keys, and unknown fields in the PUT (bug)

Status: open. Owned by @fabric. Found by @review's cr2 correctness review: one MEDIUM (proven) and one LOW
(`docs/review/cr2-ada747b-2ce6443.md`). Still present at claude/landing 9429ac65. Introduced by 9f8b3071.

1. **MEDIUM: two room keys that differ only in case** (internal/link/launchcaps.go:51 and :63).
   - `{"rooms":{"SG3":1,"sg3":50}}` passes `check`. `For` then answers from whichever key the map yields first, so
     sg3's cap is 1 or 50 at random.
   - Fix: in `check`, reject a key that folds to one already seen. Or fold keys to lower case when saving.
   - Test: `check` refuses that body. Or, if folding, `For("sg3")` answers one number across 200 calls.
2. **LOW: the PUT accepts unknown fields** (launchcaps.go:134).
   - `{"room":{"sg3":5}}` saves an empty set and answers 200, which puts every room back on the default cap.
   - Fix: `dec.DisallowUnknownFields()`, with a test that sends a misspelt key and gets a 400.
