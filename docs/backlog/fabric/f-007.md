# f-007: provision-room codex install, bare -SmokeTo, -Restart

## What was wrong

- The Unix codex install kept only the first file of `codex-<triple>.tar.gz`, which holds one file. The helper
  `codex-code-mode-host` is a separate asset, so codex was broken until fixed by hand on m1mini.
- A `-SmokeTo` handle without `@` is not found from the remote room.
- No way to restart a remote room short of `-Remove` and a fresh provision.

## What was done

- Codex: npm into `~/.local` when node and npm are on the login PATH, else the whole `codex-package-<triple>`
  release under `~/.local/share/codex/<version>` with a wrapper (not a symlink, codex finds `codex-resources`
  relative to its real exe). Windows the same shape. `Invoke-Remote` deflates scripts over the 7800 char limit.
- Bare `-SmokeTo` gets `@$env:ATRIUM_ROOM`.
- `-Restart [-Yes] [-Force]`: plan first, refuses over live cards (exit 9) and a sticky-stopped autostart (exit 10),
  uses `atrium stop`, never a kill.

## Proven

- Codex package and npm branches on m1mini under throwaway `/tmp` homes, package branch on claudevm.

## Left

- `-Restart` has not been run. claudevm has no room, so it needs a real provision first.
- npm branch on Windows, the `Invoke-Remote` deflate path, and the bare `-SmokeTo` rule are parse-checked only.
- `--state-dir` for the state dir probe.
