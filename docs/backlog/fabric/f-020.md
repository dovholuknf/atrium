# f-020. Notify's question and finished reasons never fire (bug)

Status: not started. Owned by @fabric, with the room's `/v1/state` payload shape. Found by @review's cr48 correctness
review, MEDIUM, proven (`docs/review/cr48-2d0ac78-ada747b.md`). Introduced by 83aaae28 (f-017).

`NotifyIdentity` (internal/link/notify.go:154-191) reads `questions_at`, `open_questions`, `turn_ended_at` and
`unseen` at the top level of a card. Rooms announce `/v1/state`, the raw `store.Task` rows (api/state.go:42-58, kept
whole by link/announce.go:279-316), which carry none of them. They live in `store.SeenView` (store/seen.go:83-98),
which `/v1/state` does not send. So a question and a finished turn both notify as `input`, and `finished` never
fires. The tests pass because they build flat payloads by hand.

Proof: `TestCR48RoomPayloadNeverCarriesQuestionOrFinished` in the run folder's `link/scratch/internal/link/`
(`D:/worktrees/claude/reviews/github-dovholuknf-atrium/cr48-2d0ac78-ada747b`). A fix wants a test that marshals a real
`store.Task` and its `SeenView` the way a room does.
