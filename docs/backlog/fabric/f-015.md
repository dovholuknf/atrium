# f-015: codex as a smoke case in provision

Item 4 of `docs/fabric/room-requirements-design.md` section 7. The requirements check calls provision's `-SmokeOnly`, so it
needs one smoke that covers every runner a room has, not a claude-only one.

## Built

- `Invoke-Smoke` loops over `-Runners` plus `-Install` (or `-SmokeRunners`, which accepts `claude,codex` as one
  string). Steps are `smoke:<runner>`. A failure sets exit 8 after every runner has run. No case gives `skip`.
- `Invoke-SmokeCase` is the old body, claude unchanged. The codex case launches `harness: codex` with
  `-a never -s workspace-write -c sandbox_workspace_write.network_access=true`, effort low, model the row's default,
  a prompt to run `atrium finish "<nonce>"`, and reads the nonce off the card's recap.
- `Test-CodexLogin` runs `codex login status` over ssh (the hub has no setup adapter for codex, so the runner row
  cannot say). Not logged in is a `warn` naming `codex login --device-auth`, missing is a `skip`.
- Found on the way: a launch whose title gives an existing wire name re-prompts that old card, so a fixed smoke title
  never saw its new nonce. Titles now carry the nonce.

## Known

- `-SmokeOnly` has no clone path, so it falls back to the remote home, where cards on m1mini never start (item 67).
  Pass `-SmokeCwd <clone>`. f-014's check should pass it. Proof used
  `-SmokeCwd /Users/claude/git/github/dovholuknf/atrium`.
- The signed-out warn path was not exercised live, since both rooms are either signed in or without codex.

Proof: m1mini `-Runners claude,codex -SmokeOnly`: both ok in 6s and 9s, exit 0. sg3 `-SmokeRunners codex`: skip, exit 0.
