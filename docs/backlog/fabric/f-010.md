# f-010. Cross-room cull, the hub side

Status: DONE, hub side in claude/main (`9ace4fc1`, cullSince `4c0f73b9`). Owned by @fabric (hub side). The design is @rnd's
`docs/rnd/merged-cull-design.md` (e86abb7 on claude/rnd), section "Across rooms", approved by atrium-87300. @runtime
builds the room side: `atrium merged`, the mark, the grace, the hold, the sweep, the proof itself and the room's
tip check.

## What is true today, found in the code

- `atrium_cull` is the hub's control tool (`internal/link/control_mcp.go` `cullHandler`). It resolves the card with
  `resolvePeer(room, ...)`, which only looks in the caller's room. `atrium_exit` uses `resolveCard`, which splits
  `name@room` and `room~id` (item 68) and hands back the owning room as `scope`. So failure 1 is the cull not using
  the resolver its neighbour already uses. It lives in `internal/link`, so it is ours, not @runtime's as the design
  says. @runtime has been told.
- A 404 from the room already becomes "that room is older than atrium_cull. exit the worker with atrium_exit and
  remove its worktree by hand". It does not name the room's build or the build that is needed.

## What we build

1. **Route a cull to the owning room.** `cullHandler` uses `resolveCard` and posts to `scope`, and answers with
   `namedFrom`. The self-cull check compares against the caller's own room. `atrium_cull t-003b@m1mini` and
   `m1mini~<id>` reach m1mini.
2. **Carry the proof.** The cull body gains `proof: {into, tip}`. The hub passes it through to the room untouched,
   and never makes or checks one itself. The field name and shape are agreed with @runtime before the build.
3. **Route a mark.** The mark this machine's room sends for a fetched `<room>/claude/<id>` reaches the owning room
   through the hub by the same `X-Atrium-Room` route. Check the proxy passes @runtime's mark endpoint, and add it to
   anything that allowlists routes (the guest filter must NOT allow it).
4. **A room too old for cull.** A bare 404 on the cull or mark route becomes `<room> build <x> predates cull (needs
   <sha>). Update the room.` The build comes from the room's hello (Attached). The answer says the mark is kept, so
   the cull runs once the room is updated.
5. **The binary floor.** The cull endpoint's commit goes into `atrium.requirements.yaml`'s binary floor key
   (requirements design, question 4).

6. **`/v1/preflight` through the hub** (asked by @runtime with r-018 at 2c67bca). Add it to the hub's fan-out
   allowlist (`internal/link/fanout.go`) as a per-room route, answered by the one room in `X-Atrium-Room` and never
   merged across rooms. Keep it off the guest allowlist. Folded in here because it is the same kind of change as
   routing the mark, and requirements section 7 item 6 needs it.

## Names agreed with @runtime (2026-09-29, r-019 builds the room side)

- Cull body: `tip` FLAT beside the existing `into`, as r-019 built it (corrected 2026-09-29: this said
  `proof: {into, tip}`, which the room would ignore). The room accepts it only when its worktree `HEAD` is `tip`.
- The mark: `POST /v1/merged`, body `{into, branches?: [..]}`, answer `{marked: [{card, cull_at}]}`. It is what
  `atrium merged --into` calls on its own room, and the room finds the covered cards itself.
- The hold: `POST /v1/tasks/{id}/cull/hold`, body `{by, hold?}`, and only `true` is accepted (`hold=false` is a 400).
  Owned by r-019: it adds `hold` to `atrium_cull` and the hold branch in `cullHandler`. This item does not add it.
  The hold routes across rooms because that branch uses the same `scope`.
- The chip's data is on the card view: `cull_at`, `cull_into`, `cull_held`.
- All of it is on the room's human listener, and none of it goes on the guest allowlist.

## Tests

`atrium_cull` for `name@room` and `room~id` reaches the owning room with the proof body unchanged. A bare 404 from a
room answers with the room's build and the needed sha. A worker on another room still cannot cull itself.

## Built

Branch `claude/f-010`, all in `internal/link`.

- `cullHandler` resolves with `resolveCard` and posts to `scope`, names the card with `namedFrom`, and refuses a
  self-cull only when the card is on the caller's own room. It gained `tip`, sent flat beside `into` and omitted when
  empty, never computed or checked here.
- `predates.go`: a bare 404 on a cull, hold or mark route becomes `<room> build <x> predates cull (needs <sha>). Update
  the room.` The build is the room's hello (`Hub.Rooms`). The handler says it for the cull, and `Proxy.rewrite` says it
  for the hold and the mark, which are piped through and would otherwise reach the caller bare. The status stays 404.
- `cullSince` is the one constant for the sha, set to r-019's head `bce003b`. **It must be updated to the commit
  r-019 lands as on claude/main.**
- The mark (`/v1/merged`) and `/v1/preflight` needed no code: the proxy pipes everything with `X-Atrium-Room`. They
  are deliberately in neither `merged` nor `borrowed`, so with several rooms attached and none named the hub asks
  which room (409). A comment in `fanout.go` says so, and `cullroute_test.go` locks it.
- Guests: `guestHandler` is an allowlist and none of the four routes is on it (a guest gets a GET on its own card
  and a few static paths), so nothing changed there.
- The binary floor: `internal/requirements` has only `atrium.min`, a repository's floor on the binary it is opened
  with, and no floor of atrium's own that a room is held to. None was invented.
