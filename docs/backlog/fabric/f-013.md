# f-013: room-git.ps1 init -Check, and atrium.requirements.yaml at the root

Items 3 and 8 of `docs/room-requirements-design.md` section 7.

## What and why

`room-check.ps1` (f-014) needs to ask "is this room's git ready" without changing anything, and `init` is the only
thing that knew. A check mode that writes nothing, here or there, is safe against a room in use. And the file the
whole design is about had never been committed at atrium's root.

## Built

- `room-git.ps1 init <room> -Check` prints `room-git <step> <status> <detail>` for remote, git, clone, checkout and
  fresh, plus a `warn` when the clone's work tree is dirty. Exit 0, 2, 3 or 4 as in the script header.
- `atrium.requirements.yaml` at the root is section 2.1's file. The parser accepted it unchanged.
- Proved read-only on m1mini (stale `hub-main`, exit 3), sg3 (exit 0) and claudevm (no remote, no clone, exit 3).
