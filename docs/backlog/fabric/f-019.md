# f-019: the hub owns the integration branches, and atrium moves code between rooms (design)

Raised by clint 2026-09-29. Status: design WRITTEN and reviewed (`docs/fabric/git-sync-design.md`, @rnd, with @fabric's
review of the hub side). Stage 1 is being built by @rnd's worker f-019b. @fabric reviews the hub half. Decision 19 in
`docs/fabric/hub-decisions.md` settles the direction. It extends f-002 (room-owned git) and reverses f-002's "the hub
stays out of it".

Stage 1 LIVE 2026-09-30 on sg3 and m1mini (@fabric): both rooms are `git:true`, the hub syncs claude/main into their
clones, and a worker's branch on each was collected home. How a director uses it: `remote-workers.md` here. Stage 2,
the worktree atrium makes on launch, is not built.

Why: the m1mini room had no `claude/main`, and fixing it took two pushes that no agent may run, because the tool
hook refuses every git command that reaches a remote. Today code reaches a room by a person, or by an agent
spending tokens on `scripts/room-git.ps1`. The hook rule is right, so the transfer belongs in atrium's code.

What the design has to answer:

- Where the hub keeps a bare repository per repo, and how it is backed up. `VACUUM INTO` covers `hub.db` only.
- The transport over the room's link: git smart HTTP through the hub's proxy, or a bundle per transfer.
- The room side: a clone per repo fed from the hub, and a worktree atrium makes for each card it launches.
- How a finished card's branch reaches the hub, and the merge queue that lands it, with its checks, in order.
  The queue is rows in the hub's store, so a hub restart loses nothing (decision 17).
- What replaces `scripts/room-git.ps1` (init, push-base, fetch, remove) and the manual `claude/main` on each room.
- Which agent-facing surface stays: an agent commits on `claude/<id>` and finishes, and nothing more.
