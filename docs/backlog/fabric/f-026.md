# f-026. A legacy overlay attach must not bump a proven room off its name

Status: done, passed by @review (`f-new-review-e738577e.md`), lows 3 and 4 fixed. MEDIUM. Owned by @fabric. Raised by @review on 2026-09-30,
from reading f-022 (326b374a).

`Hub.control` refuses a second attach under a taken name only when both keys are non-empty. A legacy overlay
connection has key `""`, so under the default `overlay_legacy allow` it replaces an attached certificate room of the
same name. Any peer the overlay admits can then bump a proven room and take its name. This is no worse than before
f-022, but it means a proven name is only real after `atrium rooms legacy refuse`.

To build:

- Refuse a keyless attach when the room attached under that name has a key.
- Refuse the legacy path for any name that has enrolled a certificate, whether or not it is attached now. The
  hubstore knows which room ids spent a join secret.
- Test: attach a certificate room, dial a legacy connection with the same name, and expect a refusal with a
  `room-unproven` audit line. Also cover the same legacy dial while the certificate room is detached.
- A legacy room that never enrolled a certificate keeps attaching as it does today.

## As built

- The check is in `Hub.take`, before the kinds split, so relay, announce, data and git are covered as well as
  control. Relay was the wider hole: it only asked `Has(name)`, so a legacy dial could relay as an attached proven
  room.
- "Enrolled" is `room.enrolled_at` (migration `0006_room_enrolled`), not the `joined` audit line, because the audit
  is trimmed at 5000 rows and a record that ages out fails open. Backfilled from `joined` lines, set by `Spend`, and
  set again whenever a room attaches with a certificate, which covers a line that had already aged out.
- `Hub.control` also refuses a keyless attach over a keyed one, which before slipped past the key comparison.
- The refusal is reported at most once per name every ten minutes, since whoever it is redials on a backoff.
- A store read error refuses the old path for that one name, unlike `LegacyRefused`, which allows on error.
