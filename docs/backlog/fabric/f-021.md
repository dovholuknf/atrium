# f-021: the control MCP shows a worker a worker's tools

Status: design, for @rnd before anything is built. Owned by @fabric. From `docs/rnd/gateway-fit.md` section 4, idea 3,
filed by atrium-87300 2026-09-30.

## The problem

Every session sees all eleven control tools. A worker sees `atrium_launch`, `atrium_exit`, `atrium_cull`,
`restart_atrium` and `atrium_wake_after_restart`, and is kept from them only by handler checks and one line of its
lean system prompt. Those five tool descriptions are also long, and every worker pays for them in context at every
start.

## Design

1. **Two tool sets, two servers, built once.** `full` is today's eleven. `worker` drops launch, exit, cull,
   `restart_atrium` and `atrium_wake_after_restart`, and keeps status, peers, say, report, task and alias. Both
   servers are built at startup, and `handler()`'s `getServer(req)` picks one per request, which the SDK already
   allows (`func(*http.Request) *mcp.Server`). A tool the caller's server lacks answers "unknown tool", so a client
   holding an old list is refused by construction, not by a check someone can forget.
2. **The class comes from the card's tags**, looked up on the room by `X-Atrium-Agent` and `X-Atrium-Room`: a card
   tagged `atrium:subagent` without `atrium:director` is a worker, and everything else gets `full`. That covers
   directors, @merge, and sessions a human started, which carry no tags. The answer is cached per (room, agent) for a
   minute, so a session's `tools/list` and its calls do not each cost a lookup.
3. **Fail to `full`.** A lookup that fails (a quiet room, a card not found yet at the session's first connect) serves
   the full set. This is tidiness and a context saving, not a boundary: the identity header can be spoofed, and a
   hiccup must not strip a director of the tools it runs on.
4. **No opt-out tag.** A worker whose brief needs a director tool is launched as a director. See the review below.
5. **Fixed per connection.** Claude Code reads the tool list at connect, so a card whose tags change keeps its list
   until it reconnects, which is at its next start. Nothing sends `list_changed`.

## Tests

A worker's `tools/list` has the six tools, and a call to `atrium_cull` answers unknown tool. A director and an
untagged card get eleven. A failed lookup gets eleven. The cache answers a second request without a
lookup, and expires.

## Reviewed by @rnd (2026-09-30): accepted

- Dropping `atrium_exit` for workers is right. A worker ends itself by reporting and finishing, and exiting other
  cards is a director's job.
- **No new tag.** Point 4 above is dropped: a worker that needs director tools is launched as a director
  (`atrium:director`).
- MCP clients read `tools/list` once at initialize, so the class that counts is the one at the session's first
  request. A retag lands at the worker's next session start, not mid-session.
- **THIS IS NOT A BOUNDARY.** Failing open to all eleven on a failed lookup is right because of it. The identity
  header can be spoofed by anything on loopback, and the handlers keep every check they have today.
