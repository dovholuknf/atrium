# u-037: a Changes view per card, its worktree diff, and selected lines sent to the card as a prompt

Status: design only, clint ranks. Nothing is built, and nothing is scheduled.

Filed by @ui for @rnd, from the orchestrator, 2026-09-29 ~23:20. Source: `docs/rnd/competitor-features.md` item 3
(Superset, Agent Orchestrator, Orca and cmux all ship it). The design is @rnd's, at
[`docs/rnd/changes-view-design.md`](../../rnd/changes-view-design.md). Where this file and that one differ, the
design doc wins.

## What it is

- A **Changes** view on a card: the card's worktree diff against its base branch, what the agent has changed so far.
- Drawn with the board's existing diff styling, so it reads like every other diff atrium shows.
- Select lines in the diff and send them to that card as a prompt ("why this", "undo this hunk"), quoted with the
  file and line numbers so the agent knows where to look.

## Who builds what

- **The endpoint** (the diff itself, computed on the room, bounded, contained to the card's worktree through
  `internal/safepath`): @review's or @runtime's, to be decided between them.
- **The board** (the view, the selection, the send): @ui.

## Board questions to settle before building (for the design review)

1. Where it lives: a tab in the card's details, a pane beside the terminal, or both. On a phone it is a full sheet.
2. Sending a selection: typed or queued. It goes through the same say path as the composer, so the typed versus
   queued rule of `/m`'s compose applies, and the card's held-line notice covers a busy line.
3. Refresh: event driven only (the board has no polling). A repaint on the card's turn end or a tool event, never a
   timer. What the endpoint pushes, if anything, is the endpoint's call.
4. Size: a large diff is cut on the room, with a line saying so, never by the browser after the fact.
