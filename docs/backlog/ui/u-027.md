# u-027: usage tab, by card and the cache reads toggle, and a cumulative token line

From clint via the orchestrator, 2026-09-29 ~21:52. BACKLOG ONLY, not built under the hold. Screenshots:
`.atrium/incoming/20260929-215150-pasted.png` (now) and `20260929-215256-pasted.png` (before the money removal).

## What clint saw

1. **"by card" seems to ignore the cache reads toggle.** With cache reads off, the burn rate leaves them out, but
   the by-card totals and sparklines look like they still count them (atrium 4.6M, teal bars).
2. **The toggle's label does not say its state.** It reads `cache reads` either way, pressed or not.
3. **The cumulative graph is gone.** The old "cumulative est. cost" line chart went with the money removal.

## What the code says about 1

The totals already follow the toggle. `ucCards` (js/usage-charts.js) sorts and totals by `ucShown`, and each
card's per-bucket series is built with `ucShown` too (line 229, and js/usage-groups.js:70 for groups). In the "now"
shot the tiles add up to about 41.5M, which is the counted total in tokens by kind (32k + 8.7M + 1.9M + 31M), not
the 2061M of cache reads.

What misleads is the colour. The sparkline bars are `uck-cost`, `rgba(var(--teal-rgb), .8)`, which is the cache
read swatch (`uck-read`, the same teal) at a tint. So with cache reads hidden, the by-card tiles are drawn in the
one colour the legend says is not in the charts.

## Build

1. **By card and groups draw in a neutral colour** that no kind uses (or stacked by kind, like the burn rate,
   if that reads well at 40px). Either way, no teal when cache reads are hidden. Rename `uck-cost` while there,
   since there is no cost any more. Headless check: with the toggle off, no by-card or group bar has the
   cache read fill, and each tile's total equals `ucCounted` of its sums. With it on, the totals equal
   `ucTokens`.
2. **The toggle says its state**: `cache reads shown` when pressed, `cache reads hidden` when not, with the swatch
   kept. `aria-pressed` stays. Update the tooltip to match. Headless check: the label flips with a click and with
   a settings event from another tab (`usage_cache_reads`).
3. **A cumulative token line, back where "cumulative est. cost" was** (between tokens by kind and tokens by cause).
   Counted tokens summed over the range, oldest on the left, following the toggle (counted only when hidden, all
   five kinds when shown). The axis shows 0 on the left and the range total on the right, like the old
   `$0.00 ... $296.85 est.` Clint calls it a projection. Tonight's reading is a running total to now. Whether
   it also extends a dashed line to the end of the day at the current rate is an OPEN QUESTION for clint.
   Headless check: the last point equals the range total shown in the by-kind line, and the line never goes down.

## Decided by @ui (clint asleep, directors decide, 2026-09-30)

- **Projection: both.** A solid running total to now, then a dashed line from now to the end of the range's last
  local midnight at the rate of the last hour, labelled `at this pace: 58M by midnight`, on the 24h and 7d ranges
  only (the x axis extends to midnight for it). It is omitted on 1h and 6h, and when the last hour is empty. It says "at this pace" like the limits row does, since it
  does not see the future.
- **By card: one neutral colour**, a new `--usage-bar` variable (defaulting to the label colour at about 70%) that
  every skin can reach. Stacked by kind was rejected: at 40px tall five colours are noise, and the tile's job is
  "who spent the most", which one colour answers.

Money. The dollar figures stay removed.
