# u-009: the board is driven by its event stream

The standing rule (clint, 2026-09-29): the board is a single page driven by events (SSE and websockets), never by
polling state. The only poll allowed is the visible-tab safety resync, at 60s or more.

## What changed

- `js/cards.js` holds the one copy of the cards. Every view paints from it: `renderBoard`, `renderStack`,
  `renderTermList`, the switcher, `landOnATerminal` and the prune count.
- A `task` event with `row: 1` (a complete `/v1/tasks` row, r-009) replaces that card and repaints. It makes no
  request. A `task` event without it, from an older room, pulls `/v1/tasks` at most once every 5s. That pull is
  trailing and single flight.
- `task-removed` with an id deletes that card. Without an id (the sweep), the list is read again.
- Waiting is worked out from the cards (`cardsWaiting`, the `st.Waiting()` filter). `/v1/waiting` is never fetched.
- Permissions and the remote queue are read at load, on `permission` and on a resync. `renderPerms` and
  `renderTermPerm` read that copy.
- Shares are read at load, on a resync and on `share-progress` done. Health is read at load, on a resync and on
  `halted`.
- A pass fetches only what an event marked (`want` in settings-spine.js). A pass with nothing marked repaints from
  the store.
- The 10s poll is gone. `startResync` runs a full pass every 60s while the tab is visible, and again when it becomes
  visible.
- Measured by the headless `eventDriven` and `idleBudget` sections (mocked endpoints):

| | before | after |
|---|---|---|
| `/v1/tasks` in 30s of task events without `row` | 63 | 5 |
| `/v1/tasks` in 30s of task events with `row: 1` | 63 | 1 (the resync) |
| `/v1/waiting` over the section | 130 | 0 |
| tray or sort click | waits on a `/v1/tasks` fetch | paints in the same frame, no request |
| hidden tab | resyncs | nothing |
| idle board, 60s, a task event every second | 358 requests | 5 requests |

## Asks

- **@runtime** (r-009, done at 8ae9c3f): every `task` event is a whole `/v1/tasks` row with `row: 1`. The board keys on
  it. Older rooms keep the 5s throttled pull.
- **@runtime**: a findings-changed event for a card's worktree (u-009b). The walk drawer infers from `task` events for
  the card today.
- **@runtime**: a `shares` event when a share starts or stops, from any tab. Stopping from another tab is seen only at
  the resync today.
- **@runtime**: the typed-line state pushed on the attach socket (say a `typed` frame) instead of polled, so the
  typing-gate readout needs no clock.
- **@runtime / @fabric**: confirm that a permission request on another room raises `permission` on this board's
  stream. The remote queue is read only on that event and the resync.
- **@fabric**: send `rooms` on the room-scoped stream (`/v1/events/room/*`) too, so a board scoped to one room hears
  membership changes without the 60s resync.
