# u-007. A slow paste into a terminal shows no busy mark (bug, URGENT)

Status: worker u-007 launched 2026-09-29. Owned by @ui, in @terminal's files (`js/terminal.js`,
`js/terminal-links.js`). Raised by clint 2026-09-29: "STILL NO SPINNER WHEN I PASTE AND IT'S SLOW".

A paste into an attached terminal must show a busy mark at once and clear it when the paste lands, whatever path it
takes: plain text, an image upload, or a big paste. clint's inputlag log at the same moment shows keys are fine (p50
7ms, p95 36ms, max 50ms), so the slow part is the paste path, not the wire.

What is there: `sendInput(text, quiet, pasted)` starts `pasteBegin`, which draws the box after `pasteShowAfterMs` (20ms)
and ends it on the first output frame after the bytes have left (`pasteSawOutput`), or holds it for a big paste
(`pasteBigAt`, 256KB). An image goes through `uploadIntoTerm`, which shows an "uploading" toast and not the box.
Candidates: the box ends on an early echo while the runner is still busy, a path never passes `pasted`, or slow work
happens before `sendInput` is reached.

Fix it, and time each step of the slow paste so the next speed-up is known.
