# u-008. The walk drawer's stage 1 leftovers (feature)

Status: done on branch claude/u-008, 2026-10-05. Owned by @ui. Left out of u-005 (the walk drawer,
`docs/rnd/review-tab-design.md` stage 1) by its worker, 2026-09-29.

All four were open on claude/main bcdbb267 when checked.

- **Context past the hunk.** Done. `walkTenant.headOf` reads `src/<diff path>` through `files/text` the first time a
  file is drawn and repaints when it lands. The buttons then grow past the hunk, and the count is the file's own. No
  `src/` means no change.
- **Removed lines.** Done. `walkParseDiff` keeps `-` lines as `t: "-"` with no number, drawn `.wk-l.del`.
- **The phone's bottom sheet.** Done at 900px and below. The terminal is `#t-screen` moved to the bottom and translated
  off it, with `#walk-sheet` as its handle. `walkSheet()` toggles `.sheet-open` on `.term-body`, and `a` opens it.
- **Looked at in a real browser.** Headless Chromium over a made-up run folder (no live walker card was used).
  Screens in `docs/screens/u-008/`. The headless case is `walkContext` in `scripts/test-board-headless.js`.

Not done, on purpose:

- A finding of a pulls row (`GET /v1/prs/{id}/findings`) gets its hunk from the daemon as a string. The drawer parses
  `-` lines in it the same way, but whether `internal/prreview/render` includes them in the hunk was not checked. Head
  context for those reads `src/` of the walker card's folder, which is only right if that is the run folder.
- Only the nearest hunk is spliced into the head context. A second hunk of the same file inside the grown range shows
  as plain context, without its `-` lines.
- The sheet height is fixed at 60% and is not draggable.
