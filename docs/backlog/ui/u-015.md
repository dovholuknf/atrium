# u-015: segmenting the UI tests

Status: ACCEPTED WITH CHANGES by @rnd (2026-09-29, on fbbd8fb). The changes are folded in below and marked (@rnd).
Nothing built yet except two fixes the measurements turned up (below).

## The problem

@ui runs the whole UI suite on every batch: check-board.sh, check-skins.sh and the headless board run. The headless
run is about 13 minutes on a quiet machine and 25 or more under load, and almost every batch touches one corner of
the board. clint wants the suite cut into groups, so a change runs the groups it can break, and the full run is kept
for the tip before a room restart.

The case "two branches merged untested" is dropped. Every board change now goes through @ui (standing rule 2), so
there is one tester and one branch.

### Two fixes this turned up, already committed on claude/ui

- `SKIP_HEADLESS=1` was documented and implemented nowhere, so every "full suite" ran the headless board twice: once
  inside check-board.sh and once on its own. check-board.sh honours it now (368579e).
- `groupRemove` and `linkTip` were in the HEADLESS_ONLY map and never called by the full run, and `websiteSkin` was
  in the full run and missing from the map. The two orphans pass when run. The build below makes one list the source
  of both, so this cannot drift again.

## The design

### 1. One registry of sections, with groups

Replace the `only` map and the list of `await xSection(browser, base)` calls in `main` with one array:

```js
const SECTIONS = [
  { name: "eventDriven", fn: eventDrivenSection, groups: ["events"] },
  { name: "pasteBig", fn: pasteBigSection, groups: ["terminal"] },
  ...
];
```

The full run walks `SECTIONS` in order. `HEADLESS_ONLY` takes section names or group names, mixed
(`HEADLESS_ONLY=terminal,usageLimits`), and an unknown name is a failure, not a silent skip. A new section that is
not in the registry is caught by a check in check-board.sh that greps `async function (\w+)Section` and compares the
result with the registry, the same way it already compares js/ with index.html's load order. A section can sit in
two groups (contextSize is usage and cards).

The inline checks in `main` (32s) move into a section called `core`, which is in every group run. It covers the
list paint, the blank-on-hung-fetch watchdog and dismiss, the things everything else stands on.

### 2. From changed paths to groups

`scripts/ui-groups.js <since>` runs `git diff --name-only <since>...HEAD` and prints the groups to run, from a table
in the same file:

| Path | Groups |
| --- | --- |
| `internal/api/web/js/term*.js`, `typing.js`, `keepalive.js`, `alias.js`, `solo.js`, `css/terminal.css` | terminal, rooms |
| `js/usage*.js` | usage |
| `js/themes.js`, `css/themes.css`, the skin files check-skins.sh reads | skins |
| `js/notify.js`, `js/toast*.js`, `js/tooltips.js`, `css/notify.css` | notify |
| `js/stack.js`, `js/cards.js`, `js/card-menu.js`, `js/newcard.js`, `js/peek.js`, `js/walk.js`, `css/cards.css`, `css/walk.css` | cards |
| `js/rooms.js`, `js/rooms-dash.js`, `css/phone.css` | rooms |
| `js/settings-spine.js`, `js/core.js`, `js/board.js`, `index.html` | ALL (these are shared by everything. `board.js` is here because it also drives terminal and rooms paint, the rule for any file whose name undersells what it does (@rnd)) |
| `scripts/test-board-headless.js` | the groups of the sections whose lines changed, else ALL |
| `internal/api/**/*.go`, `internal/link/**` | see 3 |
| anything else under `internal/api/web/` | ALL |
| nothing under `internal/api/web/`, no route change | none (check-board's node checks still run, 4s) |

**An unmapped path means the full suite, minus the timed group.** The table only ever narrows a run for paths it
names. The events group is the timed group of section 5 and is off locally by default. The path table turns it on
for the files it covers: `js/settings-spine.js` (which opens the event stream), `js/boot.js`, `js/down.js`,
`js/hubrestart.js`, `js/keepalive.js`, `js/seen.js`, `js/core.js` and `index.html`, and `scripts/test-board-headless.js` lines inside an events section. A poll added anywhere else is
caught by CI and the daily run, which both run the timed group. That makes the usual board batch cost its own group,
a minute or two, instead of 13 to 25.

`<since>` is the sha of the last green full run, kept in the untracked `.ui-last-green` in the @ui worktree. Only a
green FULL run writes it. When that sha is not an ancestor of HEAD (claude/ui rebased, or reset onto claude/main),
`ui-groups.js` prints ALL: a diff across a rebase silently narrows to the wrong set (@rnd).

The full run stays mandatory before a room restart and at most every 2 hours when board files changed (standing rule
1). Groups are for a batch between those.

### 3. Hub and room API changes: the mocks can lie

The headless server mocks every endpoint, so a renamed route or JSON field passes headless and breaks the live
board. Pulling in groups by route does not fix that: the mock would still answer with the old shape. So what is
checked is **the mocks against the real routes**:

- A Go test, `internal/api/routes_test.go` `TestBoardMocksMatchRoutes`, builds the real mux (and the link mux), and
  lists every registered `METHOD /path` pattern. It is the list `grep HandleFunc` gives today, about 160 routes.
- `scripts/test-board-headless.js` exports its mock table: the mock server's `METHOD /path` patterns, and for each
  JSON answer, the top-level field names (and the fields of the first element of an array). Today the mock is one
  big `createServer` callback, so the build first turns it into a table of `{method, path, handler}`. That is the
  largest part of the work.
- **No node in the Go test (@rnd).** `node scripts/test-board-headless.js --mocks` writes a COMMITTED file,
  `scripts/board-mocks.json`. check-board.sh fails when the script's table and that file disagree, and
  `TestBoardMocksMatchRoutes` reads the JSON only. Otherwise every director's `go test` would need node, or skip
  silently.
- The Go test fails when a mock path has no real route (a route renamed or removed), or when a mocked field is
  missing from the real response. **Where the fields come from (@rnd):** a route with a response struct is read by
  reflection. A `map[string]any` handler is CALLED, with httptest against a small seeded store, and the JSON keys it
  actually wrote are the list. Black box, so there is no hand-written list to drift, and handlers become structs only
  as they are touched.
- **The event stream is mocked too (@rnd).** The board relies on SSE event types and their payload fields as much as
  on routes. The mock table lists each event type name and its top-level fields, and the Go test checks them against
  what the daemon publishes.
- A real route with no mock is a warning, not a failure: the board may simply not use it.

That turns an API change into a Go test failure in `go test ./internal/api/...`, which every branch runs, not only
@ui. Then `internal/api/**/*.go` changes map to no headless group at all: the Go test is the gate.

What this does not catch: a field whose MEANING changed with the same name and type. That is what the full run
before a restart, against a live room, is for.

### 4. Time

Measured per group above. After the build, `ui-groups.js --time` prints the budget for a set of groups from the last
timed run's `TIMING` lines, so @ui can see the cost before starting.

### 5. The timed group is off locally, and one switch turns it on (clint, 2026-09-29)

The events group waits on wall-clock time (idle budgets over a minute, watchdogs, restart gates): 356s of 742s. It
is OFF by default on a developer machine. It runs in three places:

1. **In CI, every push.** The workflow stays logic-free (the rule in its header): `scripts/ci.sh` sets the switch
   and does the Playwright install. Nothing new goes in the yml.
2. **At most once a day locally,** on @ui's schedule, on the claude/ui tip. `.ui-last-timed` in the @ui worktree
   holds the date and sha of the last green timed run.
3. **When a change touches what it covers,** through the path table in section 2.

The switch is **`HEADLESS_TIMED=1`**. Not `HEADLESS_SLOW`, which is already taken: it scales every wait through
`slow()` in the headless script, and a load-heavy CI runner may well want both. With the switch off, a full run or
a group run that names `events` prints one line saying the timed group was left out and how to turn it on, so a
skip never reads as a pass. Naming a timed section by name in `HEADLESS_ONLY` runs it regardless, since that is
asking for it.

**CI does not run the headless board today.** `ci.sh` calls check-board.sh, which calls the headless script, but
nothing installs Playwright or Chromium, and the script exits 0 with "playwright is not installed" when either is
missing. So every CI run has been green on the board without running a section of it. The build adds to `ci.sh`, in
CI only (`CI=true`, which GitHub sets): `npm ci` (`@playwright/test` is already a devDependency in package.json, for the walkthroughs) and
`npx playwright install --with-deps chromium`, then `HEADLESS_TIMED=1`. And in CI a missing Playwright is a FAILURE,
not a skip, the same argument the workflow already makes for node: a skipped check that reads green on a build
machine is worse than a red one. On Windows runners `--with-deps` is a no-op, which is fine.

## Build, in order

0. `ci.sh` installs Playwright and Chromium in CI, and the headless script fails rather than skips there. Small, and
   worth doing first: nothing below is checked by CI until it lands.
1. The registry, `core`, `HEADLESS_TIMED` and the check-board registry check (small, and it fixes the drift for
   good). Also the static poll check in check-board.sh (@rnd, open question 1): fail on a new `setInterval`, or a
   `setTimeout` that re-arms itself, outside an allow list where each entry carries a one-line reason. It costs about
   4s and catches a new poll in the batch that adds it, which the timed group, off locally, cannot.
2. `ui-groups.js` with the path table and `.ui-last-green`.
3. The mock table and `TestBoardMocksMatchRoutes` (the larger piece, and it touches Go, so it is split with
   @runtime or @fabric for the link mux).
4. Later, separate item: a fake clock for the events group.

## Open questions for @rnd (answered 2026-09-29)

1. With the timed group off locally, is a new poll caught late enough to matter? **Answer: do both.** The timed group
   stays off locally AND the static poll check goes into check-board.sh (build step 1).
2. `map[string]any` handlers: a hand-written field list, or structs? **Answer: neither.** Call the real handler with
   httptest and read the keys it wrote (section 3).
