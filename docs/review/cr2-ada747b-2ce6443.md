## MEDIUM

### store 01: the r-040 guard makes Claim succeed with the card unnamed (r-048)

- **The store behaviour.** `refreshObservedAt` now looks for another row that holds `obs.WireName`. On a hit, it
  logs and sets `obs.WireName = t.WireName`. `Claim` (intake.go:417) calls it with `move=true` on a card whose
  `wire_name` is empty. So the name it "keeps" is `""`, and `nullable("")` writes NULL.
- **The result.** The UPDATE succeeds, and `Claim` returns the card with a nil error, but the card has no name.
  Before the guard, the same input hit UNIQUE and halted the store. Neither outcome is right: `Claim` exists to give
  the card its name, and its caller (daemon/launch.go:1019) treats nil as "named".
- **How it is reached.** `launch.go:1001` picks `agentName` from `launchedName`, with no lock held across
  `WireNameHeld` and `Claim`. Two launches of the same title onto two offered cards can both see the name as free.
  - The second `Claim` leaves its card unnamed, while its runner starts with `ATRIUM_AGENT_NAME=<the name>`
    (launch.go:1069).
  - The post-spawn Register (launch.go:1164) matches by name first. So that runner attaches to the first card, with
    its history and its permission rules.
- **What is proven.** The store behaviour is proven. The end-to-end race is not.
- **On landing.** It is unchanged: tasks.go:321 and :371, and intake.go:443.

### link 01: room keys that differ in case give a random launch cap (f-027)

- **The cause.** `For` loops over `lc.Rooms` and returns the first key with `equalFold(name, room)`. `check` (line
  61) rejects only empty names and out-of-range numbers, so `{"rooms":{"SG3":1,"sg3":50}}` is saved.
- **The result.** Go's map order is random, so sg3's cap is 1 on one launch and 50 on the next. The cap is the
  backstop on machine load, and `GET` shows both keys, so the operator cannot tell which one is in force.
- **Proof.** `For(sg3)` answered `{1, 50}` across 200 calls, and `check()` returned nil. The finding was introduced by
  9f8b3071.
- **On landing.** It is unchanged: launchcaps.go:51 and :63.

### link 02: the control audit line writes caller text whole (f-028)

- **The rule it breaks.** The file header says "NEVER A PAYLOAD ... a describe function never reads a text field".
  Yet several describers write caller strings:
  - `describeAlias` writes `in.Alias`;
  - `describeCull` writes `in.Into`;
  - `describeLaunch` writes `in.Room` and `in.Runner`;
  - `describeSay` and `describeExit` write `in.To` and `in.Card`.
- **Nothing bounds them.** Only the outcome is cut, to `auditErrMax`. `RecordAudit` (audit.go:69) and
  `hubstore.Store.Log` (hubstore/audit.go:59) store the detail as given.
- **The result.**
  - Any loopback caller can write a line of any size.
  - A newline lets it start a second line that reads `by orchestrator@sg3 (claimed): cull X, ok`.
  - The line is written even when the handler refused the call.
  - The board shows this log, and it trims by row count, so one row can be megabytes.
- **Proof.** A 1 MiB alias plus `\n` gave a `what` of 1048652 bytes with a newline in it. The other describers have
  the same shape, by reading. The finding was introduced by ba732202.
- **On landing.** It is unchanged: `auditDetail` at ctlaudit.go:66, and `describeAlias` at :179.

### link 03: `input` is never sent for a card with no recorded turn end (f-029, a question)

- **The gate.** `case p.Status == "needs-input" && sent && p.Seen.TurnEndedAt == ""` drops the card. It was meant
  (ec223460) for a session that has only just started, but what it tests is that no turn has ever ended.
- **Why that matters.** `turn_ended_at` is written only by `store.NoteTurnEnded` (store/seen.go:225), through
  `daemon.noteTurnForSeen` (daemon/seen.go:53). The Stop hook is optional. So a session with no Stop hook, or one
  joined part way, may never be told about.
- **What is not proven.** The slice did not trace every way a card reaches `needs-input`.
- **On landing.** It is narrowed: notify.go:246 now adds `&& report == ""`, so a session that reported is still
  notified. The question stands for a card that never reports.
- **The question for @runtime.** Can a card reach `needs-input` and stay there with an empty `turn_ended_at`?

## LOW

- **store 02 (r-048).** `if derived && task.WireName != obs.WireName { obs.WireName = task.WireName }` also fires
  when the card's name is empty and the guessed name is free. The card then stays unnamed, and every lookup by wire
  name misses it: `atrium tell`, the permission chain. Proven. Fix: apply it only when `task.WireName != ""`.
- **store 03 (r-048).** No store test calls `WireNameHeld`. Its contract has no assertion: every status, a qualified
  name, and an error answering true. The doc on `launchedName` (daemon/launch.go:1368-1373) still says a dead card's
  name is free to take back. `WireNameHeld` now answers true for done and archived cards, so the comment is the
  stale part.
- **daemon 01 (r-049).**
  - The cause: the refusal check (launch.go:944) and `leanOptions` (lean.go:692) count names after
    `cleanKitNames`, which drops blank ones. The retag block (launch.go:974, 981) tests the raw `len(...) > 0`.
  - The result: `{"lean_agents":[" "]}` with no `lean` key launches a full session but tags the card `atrium:lean`.
    The next restart, resume or keep-alive fork then starts lean, and loses the user's MCP servers and settings.
  - Proven. On landing it is at launch.go:998-1005.
- **daemon 02 (r-049).**
  - The cause: `resolveTip` runs `git rev-parse --verify <hex>^{commit}` through `gitIn`, which returns stdout and
    stderr together. A branch or tag named like the short sha wins, and `warning: refname '<hex>' is ambiguous.` joins
    the sha.
  - The result: the cull is refused, with a garbled reason. It fails closed.
  - Proven: a short sha resolved to the wrong commit, with the warning in front. On landing it is at cull.go:311.
- **daemon 03 (r-049).** Every edit to an agent or skill file writes a new hash directory under `lean-plugins/`, and
  nothing removes old ones. A crash between `MkdirTemp` and the rename leaves a `tmp-*` directory. Found by reading.
- **rest 04 (r-049).** When `cpuBusyPct` skips a reading, `sampleMachine` keeps the previous `CPUPct` and publishes it
  with the new time and no `stale_since`. Unproven. The worst case is an old number for a few ticks.
- **link 04 (f-027).** The caps PUT decodes without `DisallowUnknownFields`. So `{"room":{"sg3":5}}` saves `{}`,
  answers 200, and puts every room back on the default. Found by reading.
- **link 05 (f-029).** `io.LimitReader(r.Body, 1<<16)` cuts without an error, and the cut bytes go to every room as
  the prune body. The caller then gets a 502 with the first room's parse error, not "body too large". Found by
  reading.
